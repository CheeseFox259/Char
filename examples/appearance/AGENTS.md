# Char 外观包开发指令

根据当前用户的角色、风格、参考和行为需求制作可导入的 `.charpet`。不预设造型，不将示例外形作为交付。目标是完成开发与基本验收，最后给用户完整GUI步骤，由用户验收实际使用。

## 1. 从这里开始

本文件上两级目录为SDK根，含 `Package.swift`；独立项目使用用户给出的SDK路径。首先只读SDK根的 `docs/appearance-development.md`、`docs/pet-skin-format.md`；有跟随、每边造型、主题、气泡样式、音效或脚本需求，再读 `docs/appearance-api.md`（完整字段、默认值、预算、动作、例子及失败处理都在这里）。不遍历宿主Sources或历史会话。只有文档无法解释的具体契约缺口才定点查源码并报告宿主问题，包开发不修改Char。

默认工作区 `Resources/Skins/<形象slug>-work/`，用户指定独立目录则采用该目录。固定SDK根、工作区和输出绝对路径；参考、生成器、预览/报告留在工作区，最终包输出到该工作区 `packages/`。重建脚本从任意当前目录调用都产生相同包。开始便创建目录与本次能力/资源计划，不逐模块等用户“继续”。无法推断的关键视觉选择集中问一次，期间推进工具/格式准备；等待授权与有效工作时间分开记录。

## 2. 最短制作路线

1. 查现有图像运行时和工具；有适用依赖就复用，仅确实缺失才隔离安装。先完成透明基准图和短idle，在棋盘/黑/白背景、36/48/88pt检查。白底参考从边界连通背景分离，保护角色内部同色；透明图与精灵图按各自格式处理。表情遮罩要覆盖眼白/虹膜/高光/眼睑和抗锯齿边缘，保护眉毛/饰品。
2. 基准可靠后扩展七组动作：idle、press、return、depart、arrive、edgePeek、edgeHide。画布一致、anchor稳定、首尾衔接；动作以缓入缓出、受控回弹和压缩拉伸体现非线性。迁移考虑宿主整体缩放，避免重复收缩。所有形象包使用schemaVersion 2；纯图片需求可省略features，只声明当前需求。
3. 独立边缘按API覆盖对应clips/anchor/rotation/mirrorX。共用资源朝底边创作，宿主持续转向四边，落位idle与反馈也同向。独立每边美术可指定rotation=0；分别预演探出、落位和隐藏，并用真实8pt内缩裁切，不能把面板边缘当屏幕边缘。
4. 需要眼睛跟随/方向转头时，先分离底图与tracking层，按完整画布归一化rect声明eyes/head；检查双影、旋转/镜像后方向与边缘裁切。不能把整张PNG说成可自动跟随。高频跟随使用原生字段，不写逐帧脚本。身体动画有缩放/旋转/移动/透明度时，用与PNG一一对应的trackingFrames记录同一正向仿射和opacity；表情用tracking.states的完整head/eyes组合。闭眼状态清除虹膜/高光层；重复PNG也检查状态刷新。身体和层使用共同索引，迁移透明端不得残留头眼。先验证一个主题的基准、跟随与一条边，再扩展，避免制作完全部资源才发现契约问题。
5. 主题、气泡和音效使用对应声明式资源：主题继承顺序、Agent图标空间、黑白背景、高亮/小泡、CLI角标、状态颜色/字体、破碎/轮换、音量/静音/冷却均按API。音频优先保留宿主支持的原文件（格式和大小/时长上限见API），不支持才转换；交付保留来源、许可及转换说明，包内只放引用的运行资源，许可放在相邻交付说明中。尽量用bindings触发动作；只有需要条件/记忆时才写同步onEvent。脚本仅返回Char动作，无外部命令/文件/网络/原生库；遵守0.5秒与16动作预算，异常有明确信息。
6. 用户要求交互/布局时声明behavior/hitRegions，保留合理默认，不用脚本重写监控、锚点或窗口系统。用户可关闭形象行为偏好。制作匹配静态appIcon，在18px/64px检查；主题可有独立图标。选择形象自动同步安装图标，说明事务重签和可能的辅助功能重授权，不能声称签名身份不变。

## 3. 最少但有效的基本验收

按 `docs/plugin-basic-acceptance.md` 外观分支执行：最终包一次生产校验 `swift run --package-path <SDK根> char-package-check skin <绝对包路径>`；实际观看七组完整预览与idle多个循环。按本次声明能力补主题/四边姿态、tracking层、bindings/script和音效格式的短检查；不为没有的能力增加测试。不重建整个App，不操作真实用户环境，不为一个角色建立完整原生验收/物理框架。

唯一PNG宽×高×4累计裸RGBA估算，包含各主题、跟随层和图标；与实际RSS分开。优先共享身体、未改变的层和帧，只有需要不同美术才复制主题资源；完整示例目标≤32MiB，SDK硬上限见API。额外表情可共享身体时间线，用状态替换头眼。应用重签不会改变构建UUID；图标恢复须匹配当前宿主，不能恢复同版本旧程序。复用已通过且资源未变的证据，修改后只复查受影响动作/接口，最终格式与完整预览确认一次后交付。数字指标帮助定位异常，不代表视觉流畅。可运行API机制样本见外观 API 指南，视觉仍由本次素材决定。

完成条件：格式有效、资源与引用齐全、透明/非空/接缝/小尺寸可辨、所有声明功能有对应基本证据、生成器可重现、已知包缺陷已修复。宿主实际组合/系统图标/音效未运行的项明确待用户验证，不把离线检查说成真实使用通过。

## 4. 交付即进入用户验收

按 `docs/plugin-user-acceptance.md` 外观分支生成已填实际路径的 `USER-ACCEPTANCE.md`，最终回复直接给完整GUI步骤：解压→设置导入→脚本确认（若有）→形象/主题→桌面与四边→鼠标/动作/音效/气泡/交互→跨屏/Reduce Motion→Finder/Launchpad→重启→删除恢复。用户无需命令；不为给说明而打开App或要求解锁，仅用户明确要求准备/代测时操作。

交付完整包、可重现生成器、动作/跟随/主题/图标预览、预算/校验与未测项。重复ID拒绝导入，更新先删除旧自定义包；删除选中包恢复默认图标/形象并停止脚本和音效。真实验收由用户完成，按反馈只修受影响路径，发布遵循用户授权。

性能需求：保持原生跟随与声明式帧索引；复用未变的身体、头眼、主题和图标文件，靠引用增加动作，按当前需求控制唯一像素总量。独立1024图标保留给安装用途，18px/64px预览检查可辨性；宿主按显示尺寸解码并共享缓存，包无需自行生成所有界面缩略图或安排清理计时器。动画16MiB与界面2MiB是宿主缓存预算，不是整包资源上限；资源预算仍按完整唯一PNG计算。

使用宿主[性能面板](../../docs/performance-dashboard.md)做用户GUI验收；纯清单形象渲染计入宿主，脚本helper可独立测量physical footprint；RSS仅作详情对照。图片缓存估算已计入宿主，共享资源只注明归属，不相加为插件总用量。按需提供步骤，不新增形象侧统计或逐帧采集脚本。
