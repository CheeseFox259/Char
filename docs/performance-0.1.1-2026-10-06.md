# Char v0.1.1 性能报告

日期：2026-10-06。被测对象为从 GitHub Release 安装到 `/Applications/Char.app` 的 v0.1.1（build 2），tag 源码 `5f789f65e6ca35364e57e395596da1c4708c7a13`。本次未修改、重签或替换安装包。

后续状态：辅助功能授权已恢复，已在正式设置界面确认“已授权”。授权后的新基线和本地优化对照见 [性能优化实测](performance-optimization-2026-10-06.md)；下文保留授权恢复前的测量条件。

## 环境与方法

- macOS 26.5.1（25F80），Mac16,12，10 个逻辑 CPU，多屏工作环境。
- 真实本机观察模式，内置集成开启；默认 Char、48 pt、18 pt 气泡距离、右边缘放置，无 Hold。
- Tabbit Automation 已授权，Accessibility 未授权。因此焦点几何走 CG 回退；不能把本次数字视作 AX 授权后的性能。
- 进程累计 user+system CPU 时间差除以墙钟时间；100% 表示占满一个逻辑核心。RSS 为常驻内存，不能等同于系统的物理 footprint。
- 每项先测 20 秒 CPU/RSS，再执行 5 秒 `sample`，栈采样开销不计入 CPU 区间。端点通过实际界面检查，测试时没有代理 UI 操作。

```sh
python3 scripts/profile-char.py <PID> --seconds 20 --sample <sample-file>
```

## 实测结果

| 场景 | 单核 CPU 平均 | CPU 时间 / 墙钟 | RSS 起 → 止 | 有效性 |
| --- | ---: | --- | --- | --- |
| 正常观察，设置关闭，零气泡（重新启动后） | **8.09%** | 1.62 / 20.014 秒 | 58.3 → 57.4 MiB | 受控静止样本；端点确认设置关闭，末次截图为零气泡 |
| 设置静止打开，未滚动或操作 | **44.67%** | 8.94 / 20.014 秒 | 58.0 → 57.9 MiB | 有效设置场景；端点 AX 树无变化 |
| 较早正常观察，设置关闭，1 个 Codex 运行气泡 | 8.89% | 1.78 / 20.018 秒 | 78.0 → 74.7 MiB | 有效；与重启后的零气泡样本不同 |
| 设置打开且发生授权界面操作 | 43.23% | 8.65 / 20.010 秒 | 78.8 → 87.2 MiB | 交互样本，不能称为静止基线 |
| 正常重复采样，设置开启时间不明 | 8.75% | 1.75 / 20.010 秒 | 74.9 → 75.0 MiB | 排除受控比较：开始设置关闭，末次检查已被用户打开 |

最新两项使用 PID 92416；较早三项使用 PID 89693。Settings 静止样本后的 stack report 物理 footprint 为 90.7M（峰值 125.9M），发生在 CPU 区间之后，不能代替表中 RSS。

证据保存在被 Git 忽略的 `build/performance-0.1.1-2026-10-06/`：`normal-cleaned`、`settings-quiet`、`normal-untrusted`、`settings-open`、`normal-untrusted-repeat` 的 `.json` / `.sample.txt`。本报告未发布原始进程栈。

## 开销组成

**设置打开是最明确的额外开销。** 静止设置栈集中出现 AppKit display cycle → `NSHostingView.layout` → SwiftUI 尺寸/布局计算。源码 `PluginSettingsView.swift` 中 12 Hz 的 `TimelineView` 更新形象预览，提供了可验证的优化切入点；还没有进行隔离预览的单变量测试，不能把全部差值归因于它。设置关闭后的栈没有持续 `NSHostingView.layout`，已有关闭窗口释放视图的修复仍有效。

**多屏焦点几何查询。** 正常栈出现 `trackFocusedDisplay` / `tick` → `WorkspaceRuntime.foreground()`。多屏跟随每 150 ms 检查，路由观察每 500 ms 检查；同一个 foreground 路径读取 CG 窗口列表、转换几何和选择显示器。AX 未授权时跳过 AX 消息，但 CG 查询依然存在。

**动画与指针时钟。** 正常栈包含 `CompanionSurface.animate`、呈现层读取、Core Animation 提交；时钟为 60 Hz，闲置变换已采用合成器关键帧。位图缓存减少重复绘制，但眨眼、视线等内容变化仍会产生局部更新。

**本地观察 IO。** 正常栈可见 `LocalObservationPoller`、`KimiObservationPoller`、目录元数据/日志 stat。已有增量读取与目录缓存，仍有文件检查与排序。

上述路径说明工作构成，不是可相加的组件 CPU 百分比。`sample` 包含等待，父子栈重叠；不得据栈计数计算组件占比。

## 下一步优化顺序

| 顺序 | 改动 | 验证方式 |
| --- | --- | --- |
| 1 | 将设置预览时钟局限在预览绘图视图，避免每帧重新布局整个表单；预览不可见时停止更新 | 同一包、同一设置位置，隔离开关预览更新，再测 20 秒 CPU；检查动画/形象切换 |
| 2 | 拆分轻量前台应用身份与显示器几何查询；共享重复结果，再评估 AX 焦点/窗口事件加回退检测 | 相同双屏场景采样；覆盖同应用和跨应用焦点移动、未授权回退，不降低跟随速度 |
| 3 | 静止指针时避免无变化的视线/命中更新，隐藏窗口时暂停无用时钟 | 分别测静止、悬停、交互；确保眼睛跟随和弹性动画仍流畅 |
| 4 | 对观察文件检查做单独测量，再评估事件提示与补扫 | 保留新会话发现、日志替换/截短、睡眠恢复的正确性 |

这次完成测量与分析，未实施这些优化，不承诺未经实测的下降比例。

## 测量范围

测量只涵盖 Char 自身；未测 WindowServer/GPU、电池功耗、长时内存趋势，也未做七气泡折叠/Hold/跨屏动画峰值测量。历史报告中的 5.75%（旧源码、零气泡）和 4.75%（隔离折叠场景）与当前数据的版本、数据根及权限不同，不能直接判断性能回归或改善。

## 同期辅助功能诊断与安装清理

系统设置开关为开启，应用实际 `AXIsProcessTrusted()` 仍为 false。重启和用户移除后重新添加均未恢复。2026-10-06 的 TCC 日志明确出现 `Failed to match existing code requirement`：授权记录要求旧哈希 `a673e26ac079d4e4344920261d48a5502dcf9231`，当前 Release 的要求为 `368a6d39e73ecb1176dd21ca0c7960337045c2b2` 或 `6d2b9a80d94743044e1cd628081651c34d6a2712`。重新添加期间日志还指向 `build/Char.app`。这证明授权记录与运行包的代码身份不匹配；设置不是缓存了错误状态。

当前包为 ad-hoc 签名、无 Team ID，不同构建的代码要求不同。为排除同名包歧义，已注销并把五个构建/下载/安装备份副本移到废纸篓；仅保留 `/Applications/Char.app`，仅一个该路径的运行进程，保留用户数据与 Release 压缩包。授权恢复仍需重新建立针对这一包的系统记录；没有修改 Tabbit Automation。

随后执行 `tccutil reset Accessibility com.cheesefox.char`，系统返回两项成功重置。用户通过绝对路径重新添加正式包，随后确认授权正常；本次性能优化前也已在正式设置界面核对“辅助功能：已授权”。长期发布需要稳定签名身份，避免更新后二进制身份变化再次影响授权。
