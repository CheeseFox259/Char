# 设置中的性能面板

设置 → 性能 → 实时采集。主指标为 physical footprint（macOS 对进程的内存记账），RSS 在“计量详情”中保留。每秒更新，关闭后保留本次结果，清空统计重新开始；退出 Char 后不保留统计。默认关闭。开启后即使关闭设置仍继续记录，需关掉实时采集才停止。

## 测量范围

| 行 | 实际测量 |
| --- | --- |
| Char | 宿主进程，包含共享的形象绘制、气泡、原生 Hook 读取及监控自身 |
| 当前形象 | 仅形象脚本 helper；没有脚本时显示“运行于宿主”。解码源图片缓存单独列出，计入 Char |
| 启用集成 | 宿主已启动的常驻适配器进程；无常驻进程时显示“运行于宿主”。相同图标按内容共享 |

不统计外部 Agent 应用、适配器子进程、短于采样间隔的 Hook/维护命令、WindowServer/GPU或独占绘图成本。Physical footprint 是系统对进程负担的记账，包含压缩内存等成本，不是插件全部独占用量；RSS 是驻留内存，包含共享映射。两者口径不同，不能直接相减或将进程行相加作为系统新增 RAM。

## 口径与开销

- CPU当前值来自进程累计用户+系统CPU时间的差分，单核100%；多核并行可能超过100%。首次采样只有基线，显示“—”，第二次开始显示CPU。
- CPU平均按有效区间的时长加权；内存平均为该指标成功采样的算术平均。不可读取的值显示“不可用”，不按0参与统计；未取得峰值时显示“—”。峰值为本次采集实际读到的峰值，不代表采样间隔内的瞬时最大值。
- 只统计开启采集后、进程可读取的区间。暂停、退出、重新启动或PID复用时重建差分基线，缺失值不是0。插件禁用/删除或换形象时，其行和本次统计在下一次采样移除。
- 后台批量调用原生`proc_pid_rusage`，同时取`ri_phys_footprint`与`ri_resident_size`，不启动ps或shell，不枚举其他应用，无重叠采集任务。1秒定时器允许150ms容差，累积计数O(1)，无时间序列或磁盘写入；默认关闭时无定时器。

## 图片缓存归属

“图片缓存（宿主内）”按解码后的CGImage `bytesPerRow × height`计数，不以PNG文件大小或整包像素总量代替。Char行是动画与界面缓存的唯一资源总计；形象/集成行是引用它们的资源子集。一个位图被CLI与Desktop共享时，各行在详情注明共享部分；不平均分摊，也不能把这些行相加。

该数值只覆盖缓存持有的解码源图片，不含当前合成纹理、AppKit内部缓存、音效与其他对象；它已经计入宿主footprint，不与适配器/脚本进程内存相加。形象与插件卸载、主题/尺寸变更、系统内存压力会释放相关缓存，操作后的下一次采样反映变化。暂存/安装图标的原始1024资源不是常驻界面缓存。

## 简短用户验收

1. 设置 → 性能，开启实时采集，等2秒：宿主显示CPU/内存，展开计量详情可看RSS和有效采样数；没有脚本的形象不显示独占数值。
2. 自然使用一个已加载适配器的集成，确认其行更新；禁用该集成后，该行在下一次采样消失。
3. 关闭实时采集，确认采样数冻结；清空统计后数据清空。无需发起模型请求。
