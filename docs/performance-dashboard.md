# 设置中的性能面板

Char 0.3.1 起：设置 → 性能 → 实时采集。每秒更新，关闭后保留本次结果，清空统计重新开始；退出 Char 后不保留统计。默认关闭。开启后即使关闭设置仍继续记录，需关掉实时采集才停止。

## 测量范围

| 行 | 实际测量 |
| --- | --- |
| Char | 宿主进程，包含共享的形象绘制、气泡、原生 Hook 读取及监控自身 |
| 当前形象 | 仅形象脚本 helper；没有脚本时显示“渲染计入宿主”，不虚构独占占用 |
| 启用集成 | 宿主已启动的常驻适配器进程；无常驻进程时明确标记 |

不统计外部 Agent 应用、适配器子进程、短于采样间隔的 Hook/维护命令、WindowServer/GPU或独占绘图成本。RSS是驻留内存，不是独占物理内存，进程间共享页可能重复计数，因此不将这些行直接求和作为系统总开销。

## 口径与开销

- CPU当前值来自进程累计用户+系统CPU时间的差分，单核100%；多核并行可能超过100%。首次采样只有基线，显示“—”，第二次开始显示CPU。
- CPU平均按有效区间的时长加权；RSS平均为成功采样平均。峰值为本次采集实际读到的峰值，不代表采样间隔内的瞬时最大值。
- 只统计开启采集后、进程可读取的区间。暂停、退出、重新启动或PID复用时重建差分基线，缺失值不是0。插件禁用/删除或换形象时，其行和本次统计在下一次采样移除。
- 后台批量调用原生`proc_pid_rusage`，不启动ps或shell，不枚举其他应用，无重叠采集任务。1秒定时器允许150ms容差，累积计数O(1)，无时间序列或磁盘写入；默认关闭时无定时器。

## 简短用户验收

1. 设置 → 性能，开启实时采集，等2秒：宿主显示CPU/RSS和有效采样数；没有脚本的形象不显示独占数值。
2. 自然使用一个已加载适配器的集成，确认其行更新；禁用该集成后，该行在下一次采样消失。
3. 关闭实时采集，确认采样数冻结；清空统计后数据清空。无需发起模型请求。
