# 插件图标获取与用户上传

目标是目标客户端的**准确官方图标**。CLI的承载终端、模型供应商与客户端是不同身份；扩展自身的图标也不代表客户端。按以下顺序处理，由开发Agent完成查找和转换，用户只需在最后一个分支上传文件。

## 1. 本地官方资源

先确认目标客户端的产品名、版本和应用身份。macOS优先读取该App的Info.plist中CFBundleIconFile/CFBundleIcons及对应资源；CLI从其官方发行包、资源目录或官方仓库取得图标。CLI与Desktop有官方共用标识时可共用，差异通过clientInterface=cli的宿主角标表达。

应用级跳转的bundle可能属于Warp等承载终端，不能据此拿终端图标代替Agent图标。客户端扩展/Hook自己的占位图也不能复用为Agent官方图标。

原始ICNS/ICO/SVG等由标准工具无损或保真转换为PNG，保留比例、颜色、透明度和图形；PNG直接复制。使用可获得的清晰版本，不放大低分辨率favicon充当精确资源。不使用AI生成或凭印象重绘商标。

## 2. 网上查找

本地未安装、没有品牌资源或身份无法确认时，主动联网搜索“产品全名 + 官方图标/logo”。依次查官方产品页、官方品牌/下载页、官方仓库及其资源。CDN文件必须有官方页面/仓库引用佐证；搜索结果排名和文件名不能证明真实性。

核对具体产品和CLI/Desktop身份，避免同名软件、公司总品牌、第三方重绘或搜索缩略图。确认后下载原始资源并打入包；在facts.md记录来源页面、资源URL、获取日期和原始/交付SHA-256。相互冲突或无法确认时进入用户上传分支。

## 3. 用户上传

查不到可靠资源时，用一次问题说明缺少哪个客户端图标，请用户直接上传PNG/SVG/ICO/ICNS，或提供本地文件路径/官方资源链接。无需用户运行转换命令。用户主动指定图标时使用其文件并标记“用户提供”，不伪称官方来源。

等待文件期间继续完成其他开发。用户明确允许临时占位时，完成声明标明“图标待确认”；未获许可不能悄悄使用字母、终端、公司品牌或扩展占位图代替准确图标。

上传文件由开发Agent验证、必要时转换并放进唯一源码树。换图标后重建同ID完整包，用户在Char设置重新导入即可；不修改用户已安装副本。当前Char设置没有单独的“上传Agent图标”控件，此分支通过开发会话附件/文件路径完成。

## 4. 打包与检查

建议源码路径`icons/<客户端>.png`，与client-extension自己的资源分开；清单icon引用包内相对路径。PNG可解码且宽高≤2048，整包≤8MiB、无符号链接；常规采用256/512/1024像素的清晰资源。方形画布保持原比例，品牌背景原样保留。

骨架支持用户提供的PNG：

```sh
python3 "$CHAR_SDK_ROOT/scripts/new-capability-plugin.py" \
  "$CHAR_PLUGIN_WORKSPACE/packages/sample-cli.charintegration" \
  --id studio.sample.cli --name "Sample CLI" \
  --bundle dev.warp.Warp-Stable --work-end studio.sample.cli \
  --interface cli --capabilities monitor,visit,lifecycle \
  --icon "$CHAR_PLUGIN_WORKSPACE/icons/client.png"
```

这只是SDK调用示范，图标文件应先按上述步骤获取。仅生成骨架时可暂不提供icon，正式测试包的图标必须已有来源或明确标记待确认。生成器只复制资源并检查基础PNG尺寸，完整解码检查由char-package-check执行。

交付前打开实际PNG，核对原始官方/用户资源；检查两端清单引用和包内文件。GUI验收看小尺寸、透明度及CLI角标，不改变图标来迁就气泡颜色。记录“来源确认”“格式通过”“用户显示确认”三项各自状态。

## 当前运行时行为

Char优先显示插件清单icon，读取后缓存；内置工作端有部分专用资源或桌面App映射，随后才尝试本地应用图标与通用占位。外部CLI未带icon时可能回退到承载终端，所以准确图标应随包交付。

网络查找与用户上传发生在开发/维护阶段。运行中的Char使用已打包的本地PNG，不在气泡绘制或状态刷新时联网。重新导入同ID包会清除图标缓存；用户无需退出Char。
