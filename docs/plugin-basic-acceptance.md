# 插件基本验收：开发者执行

本文件定义交付测试包前的检查。按包类型和**实际声明的能力**选择分支；不为未实现能力新增代码。基本验收在隔离配置根进行，真实客户端使用与 Char 界面验收交给用户，步骤见[用户验收交付](plugin-user-acceptance.md)。

## 执行策略：快测、按需检查、用户验收

**默认路径：小冒烟 → 按改动跑相关用例 → 最终快测一次 → 每包SDK检查 → 交付用户。** 以下表格是适用机制的覆盖要求，不是每次改动都跑全表。一个用例可同时证明多个不变量；同源码双包共用机制测试，各包仍各做身份/配置/握手与事件路由检查。

| 层级 | 执行条件 | 范围 |
| --- | --- | --- |
| 默认快测 | 声明了对应能力 | 真实适配器协议/退出；监控序列及采集机制；维护所属资源/共享/恢复；真实格式与各端路由。外部客户端命令可在快测中用可控桩，原生加载仍待用户确认 |
| 按需检查 | 尚缺实现所需契约、具体失败/性能风险或用户明确要求 | 一次隔离客户端发现/原生事件探测；专门性能基准；极限压力、多版本/终端兼容。只补该证据缺口 |
| 用户验收 | 基本验收通过后 | 真正客户端交互、Char气泡、点击/回城与热维护；开发者提供完整GUI步骤 |

执行规则：

- 先运行一个最小进程往返、退出及临时目录清理，确认测试辅助代码有效，再写批量用例；变量未定义等基础错误先用此路径定位。
- 用事件/响应/进程退出作为完成条件，设置与机制相符的期限；快测通常应在数十秒至约2分钟内结束，超过先检查阻塞原因。这是排查提示，不是删断言或判成功的门槛。读取一段即时日志，不用 `tail/head` 等到进程结束才暴露首个失败。
- 在本轮首次相关通过后保留证据；失败修复只重跑对应组。只改清理辅助函数就验证该函数与资源差异，不重启整个原生TUI；只改文档不重跑运行测试。最终运行文件/配置改变才使对应证据失效。
- 等待正在运行的测试完成或诊断其具体阻塞，不启动重叠副本；stdout逐行解析，Python需要即时日志时启用无缓冲。记录退出码，用所属PID清理。
- 原生探索一次失败先检查具体输入/配置，最多再做一次有新假设的定点探测；仍缺证据时，保留实现正确性检查，把原生行为交用户验证。已知插件本身的错误必须修复，不能借此跳过。
- 只有实现契约无法从文档/样本确认时才搭最小原生探测。默认不新建模型协议服务器、PTY按键编排和完整原生验收框架。已有适用样本可复用，并注明客户端版本、采集方式和对应实现；fixture不声称新的原生验收。
- 突发按**字节量超过两批**构造一次；共享写入用少量真实独立进程并对照输入集合。无需固定数千事件/数百会话，也不为两端共享代码复制完整套件。`Promise.all`加同步文件写入不能证明多进程Hook竞争。
- 读取日志时保留真实退出码；管道最后命令成功不等于测试成功。选择工具提供的返回码或保存原命令状态，不能把 `tail` 的0写成SDK通过。

**停止条件**：适用快测通过、最终各包的生产格式/inspect/路由通过、已知实现错误已修复、交付说明就绪后立即交付。未声明能力不测；原生待验证不阻塞测试包交付。已检查且实现未变的结果复用，不追加“再全部确认一次”。

## 0. 测试对象与证据

1. 从唯一源码生成最终包，记录版本、实际测试命令与相关实现/配置摘要，判断先前证据是否仍适用。开发中可测源码，交付前对生成包确认协议与资源一致；相同实现通过一次即可。
2. 临时 HOME **及客户端可能独立使用的配置/数据根**都重定向；检查客户端参数、环境和固定路径是否真的指向临时目录。HOME 改了不等于所有写入都隔离。
3. 测试必须断言预期身份、状态、帧内容与退出结果。stdout chunk 不是 JSONL 行，响应不是事件；“收到 N 行”与“脚本没报错”不能替代断言。超时后强杀应使检查失败，不能当正常退出。
4. 证据标注为生产格式、真实适配器进程、模拟/回放、隔离客户端发现或用户原生验收。每类各自给结论；未捕获的原生类别仍待验证。
5. 清理自己启动的进程、独立 tmux server 和临时数据。用户插件目录、缓存、市场与会话不属于基本验收工作区。

完成记录可用：`检查项 | 方法/命令 | 预期 | 实际 | 证据路径 | 通过/失败/待验证/不适用`。失败修复后重建包并重跑受影响项。

## 1. 所有集成包：格式、身份和图标

- 每个包分别运行 `char-package-check integration`；含进程适配器的包再运行 `char-plugin-check inspect`。调用方式见[SDK指南](plugin-development.md#5-开发与验收流程)。使用真实生产清单解码器检查所有交付配置示例，尤其 configuration 的字符串字典。
- CLI/Desktop 的插件 ID、workEnd、clientInterface 与 bundle 分别核对。CLI bundle 是终端 App；工作端不能靠进程命令中“提到了某路径”来分流。
- 图标按[获取流程](plugin-icon-sourcing.md)取得，实际打开最终 PNG 与来源对照，核对每个生成包的引用/字节。PNG 有效不证明是目标产品图标；扩展图标与 Agent 图标分开。用户提供与官方来源分别标注。
- 包内只放运行资源，入口/图标使用相对路径；将生成包复制/移动到新的临时目录再握手，路径由新宿主上下文解析，不依赖工作区或 build/Char.app。依赖在宿主实际 PATH 中可用。Hook 可以使用的客户端内置运行时不等于适配器 runtime 可用。

通过条件：每个交付包格式有效，身份、图标和配置真实可用；骨架 notInstalled 仅证明协议通，不是能力完成。

## 2. 进程适配器：真实进程与协议

对最终包启动实际入口，通过 stdin 发送 hello、inspect 和各声明方法；按 id 匹配响应。覆盖未知方法、重复 start/stop/release（如适用）、EOF/SIGTERM 与在途操作。验证 stdout 无调试文字，用户可见诊断能通过 inspect.detail/error 获取。

inspect 的安装前→安装后→更新/损坏→卸载结果合并在维护序列中检查；格式相同的坏身份/版本/入口可用小型表驱动用例，不每种都启动完整客户端。比较文件差异以确认只读。自己的配置文件存在、任何缓存 manifest 存在、客户端实际加载是三个不同证据；缓存须匹配当前插件身份与版本，不能将其他插件或旧快照当就绪。

通过条件：响应符合[协议](capability-adapter-protocol.md)，错误有真实结果，结束时退出且无残留订阅/子进程。请求总耗时遵守宿主预算，多个串行子进程共用剩余时间。

## 3. monitor：事件转换与自动采集

只对声称支持的结构化类别做映射；真实样本缺失时区分“映射测试通过”和“原生待验证”。合成反例可检验实现，不得伪装原生客户端载荷。

| 路径 | 执行方式 | 必须断言 |
| --- | --- | --- |
| 根/子身份与两端分流 | 完整开始→运行→审批/停顿→恢复→关闭序列，字段缺失/null/false/空白变体 | 子身份贯穿后续事件；不同端只发布自己的 workEnd；正文、凭证不落盘 |
| 稳定 ID | 两个共同长前缀、末尾不同的原生 ID 经 Hook 和适配器全路径 | 最终长度符合协议，映射不同且重复运行稳定，不能截断碰撞 |
| 并发 Hook | 多进程同时写同一流，解析每一条并对照输入集合 | 每条完整 JSON、身份不丢失/混合；白名单先在内存完成，再保证记录级写入 |
| 自动积压续读 | start/watch 后一次追加**超过两批**，随后不再写入，不从测试手动调用 read | 在测试期限内全量自动到达，无遗漏/重复；每批有界，仍有积压时自行续读 |
| UTF-8/半行 | 实际读取边界拆开多字节字符和 JSON 行，再补齐；含转义与冒号空白 | 字符原样恢复，半行未完成时不发布，JSON 用解析器处理 |
| 文件生命周期 | 缺文件→创建、截短、轮转、更换、再次启动 | 有明确 EOF 基线/观察代次；历史活动按约定不补播，旧缓存不误用 |
| stop/重启 | 多实例订阅同一文件，停止其中一个，再启动/退出 | 只取消所属订阅与续读；停止实例不再发事件，其他实例正常 |
| Hook 失败 | 无写权限/路径不可用/坏输入/缺依赖 | 不污染客户端 TUI，不阻断其运行；失败可从本插件去敏诊断或自检定位 |

持续定时轮询方案也要证明一次突发后无需新输入即可清空积压。监控停止/恢复、子会话与关闭水位要用序列测试，不只测试单个函数。

再用宿主 replay 检查事件解码与路由。示范 fixture 需替换 workEnd；replay 输出**最终快照**，末尾 closed 后为0是合法结果。中间提醒用停顿处截止的样本或阶段断言证明。回放不执行采集器，也不证明 Hook 已加载。

## 4. lifecycle：所有权、共享与恢复

在临时客户端配置根做资源清单与内容哈希的前后对照。适配器安装/卸载成功返回值不能替代差异检查。

| 场景 | 通过条件 |
| --- | --- |
| 未安装→安装→重复安装→升级 | 文件/注册按约定，幂等；原配置有备份；新版本能被 inspect 核对 |
| 同名外来目录、缺失/损坏归属 | 拒绝接管和删除，外来内容原样保留；路径名或 support 前缀不是所有权 |
| 插件/事件父目录内无关 sentinel | 卸载只移除确认所属文件；无关文件、备份、用户修改及显式自定义事件路径按约定保留 |
| 默认路径/空格/引号/美元符号/自定义配置根 | 序列化与命令参数各自正确，实际写入路径与清单一致 |
| 阶段写入、注册或升级失败 | 原安装可继续用，备份存在，错误明确；临时写入可恢复 |
| CLI/Desktop 共享资源 | 两种删除顺序与真实跨进程竞争都验证；owner 不漏计，一端删除不破坏另一端；最后一端按所属范围清理 |

共享操作用跨进程协调；锁竞争返回可重试或安全串行均可，不能靠同一进程内测试证明。当前 retainSharedIntegration 是内置 Kimi 提示，第三方插件应自行管理共享资源。

若客户端发现契约尚不明确，用一次隔离、只读发现检查补证据；已查证加载格式后，快测可用命令桩检查调用及结果分支。实际发现/启用/加载默认由用户验收，写文件和桩都不能作为加载证据。无法隔离或需要交互时直接交用户。当前客户端 lease/只读快照由客户端正常重启回收；清理说明同样必须限定所有权，不能用整个缓存目录 glob/chmod 或市场升级来代替卸载。

## 5. visit / origin：结果与精度

用可隔离的对象/API 测试或桩验证请求形状、预算与状态分支；最终前台交互由用户确认。没有实际前台证据时，不将模拟成功标为真实 exact。

- visit：目标存在/关闭、应用运行/未运行、同应用多会话、API 失败或超时。只激活应用为 fallback，失败为 unavailable。
- origin：capture 捕获具体对象；token 绑定 App PID 和适配器实例。check 的确定关闭为 false、未知为 null/error；active 确认原对象。旧 token/错误 PID/实例重启/重复 release 有正确结果。
- tmux：独立 server 中确认真实 pane ID，覆盖无 attached client、多 server/socket、后台 pane；pane_active/window_active 不能单独证明终端与对象已在前台。

普通请求总预算3秒，维护15秒，超时以完整请求而非每条外部命令单独累计。首次权限被拒绝时有明确结果；应用级降级不需要伪造具体起点。

## 6. 性能：分开测量并保留原始样本

设计目标及实现边界统一见[性能要求](plugin-performance.md)，不要在每个插件重建一套基准框架。超出目标时做一次有针对性的替代对照，记录真实取舍。

实现稳定后按实际机制做**一次轻量基准**；无常驻进程的配置包不测适配器空闲。先跑单次Hook/进程采样确认脚本路径、返回值、退出与清理有效，再采完整样本。只有采集/运行机制改变、具体性能异常或用户要求时重测，图标/文字变更复用相关证据。完整压力和UI端到端留给按需检查。测量要求如下：

- **Hook**：记录预热次数、测量次数、运行时、输入规模；启动→退出耗时是否包含进程启动写清楚。
- **适配器**：记录 PID、启动时间、预热/稳定等待、采样间隔与持续时间。保留同一时点 CPU/RSS 原始序列和单位，区分启动、稳定空闲和突发活动；说明 CPU 是区间增量还是 ps 自启动累计值。至少给可复核的稳定空闲时段，例如预热后连续20秒。单次显示0.0%不是长期零开销。
- **双端/共享**：每个启用 monitor 包有一个进程，记录两端合计及共享采集器/子进程；共享源码不自动合并进程。
- **延迟**：注明起止点与样本量，分开 append→适配器、Hook→适配器、宿主→气泡。使用单调时钟或说明时钟误差；本地流到 stdout 的中位数不能声称为 UI 端到端延迟。
- **结束**：退出后核对进程、watcher、timer 和临时文件。日志保持增量、有界与自动续读，不能通过丢事件/放慢响应换低开销。

报告给出条件、原始样本路径和范围；不拼接不同时点的 RSS/CPU，不将旧版本数值当新版实测。宿主 UI 成本无测量条件时待用户实测。

## 7. 外观包：数据、完整动画与预算

`.charpet` 不执行以上集成适配器分支。仅对声明能力补基本检查：变体/主题解析、叠加层、音效格式、bindings及脚本同步返回和超时。无需重建宿主或代替用户验收音效、鼠标和系统图标。对最终包运行 `char-package-check skin`，按[格式](pet-skin-format.md)检查七组动画、8-bit RGBA、anchor、帧序、路径、引用、尺寸/像素/字节预算和独立 appIcon。

实际打开最终图标，检查18px/64px辨识度；先核对透明基准、表情局部与短idle，再观看七组完整预览及 idle 多次循环，检查非空画面、透明边界、回弹和首尾。按[实际边缘坐标](appearance-development.md#边缘预演的实际坐标)分别预演边缘动作和落位idle；真实裁切、跨屏、Space、Reduce Motion 与交互仍交用户验收。帧差/运动指标用于定位异常，不能代替完整视觉检查；复用适用工具，只补具体缺口。预览通过不等于 App 组合通过。

内存估算按唯一解码资源宽×高×4累加（含独立图标），和实际 RSS 分开报告。没有宿主测量条件时给估算及待测场景，不编造 CPU 数值。最后重建/校验包并交付所有预览；用户更新须先删除同 ID 旧形象再导入，不能套用集成包更新方式。
