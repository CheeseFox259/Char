# 0008：进程能力插件与宿主返回锚点

- 日期：2026-10-06
- 状态：接受，依用户批准实施
- 取代：ADR 0007 中“仅配置已编译能力”和固定首次起点的不可配置部分；保留普通应用自由起点和应用级精度规则。

## 背景

旧插件只选择固定观察协议和精准适配器，新增客户端仍要改 Char。客户端 Hook 独立安装，开发路径随应用安装变更而失效。用户批准将监控、跳转、回城和安装维护纳入统一能力包，并兼容不同客户端与工作习惯。

## 决定

使用 v3 清单、动态工作端身份及版本1本地 JSON Lines 进程接口。客户端适配器负责原生事件、具体对象聚焦、opaque 起点标识和所属配置的生命周期；Char 负责聚合、过滤、排序、已查看、返回锚点、宽限期、快捷键、桌宠与动画。

默认保留首次起点，用户可选择最近起点或关闭记录，并可禁用应用级起点。准确 token 绑定原应用 PID 和适配器实例，失效/移除/升级后不复用；普通应用级回城不需要插件。适配器通过 inspect 区分启用意图和配置可用性，安装后重载由用户安排。

进程内动态库会扩大宿主崩溃边界并绑定语言 ABI，因此选择进程接口。它隔离协议与崩溃，但不提供权限沙箱；导入执行代码需明确提示。monitor 推送，visit/lifecycle-only 按需退出；不建立每插件高频轮询。内置旧观察和 Tabbit/VS Code 平台路径保留兼容，新软件通过外部能力接口开发。

宿主把 Hook 和内置客户端资源部署到当前用户稳定数据目录，安装器使用该上下文。导入只自检，安装/更新/卸载为显式操作，备份并只修改自己所属记录。

## 后果

新增客户端无需宿主重编译；包作者负责具体软件接口的可靠性、运行时依赖和停止清理。每个常驻适配器有独立内存成本，必须测量；包大小限制可能要求用户预装运行时。协议按能力拒绝方法和他人身份事件，精准承诺依客户端实际确认；不能保证没有可靠接口的软件精确返回。
