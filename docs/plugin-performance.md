# 集成插件性能要求

此文是集成开发指令的性能契约。适用于新插件和运行机制改变；仅图标/文案变化复用有效证据。性能实现不依赖用户代测，开发者先完成隔离基本测量，最后提供GUI验收步骤。

## 1. 设计前确定成本和默认目标

先列出实际常驻进程数、运行时、共享资源、事件源、缓存与低频操作。CLI/Desktop共用源码仍是两个monitor进程，预算按两端分别及合计记录。没有常驻能力的配置包不人为加进程。

用户指定预算优先；没有指定时，以轻量边界观察器为目标：

| 稳态目标 | 默认设计目标（非宿主协议硬限制） |
| --- | --- |
| 空闲CPU | 预热后平均≤0.5%单核；不以一个0.0%读数替代区间测量 |
| 常驻内存 | 每进程RSS≤25MiB、可取得时物理内存占用≤15MiB；双端记录两份成本 |
| 本地事件延迟 | 单条追加/原生事件→适配器stdout p95≤100ms；不含宿主500ms调度或UI动画 |
| 稳定性 | 静默和突发结束后状态/缓冲有界；不随历史日志或已关闭会话无限增长 |

依赖重型客户端SDK或运行时导致超目标时，做**一次**轻量对照（空运行时或按需/原生入口），以实测决定实现。不能把“Node本来就占这些内存”当作自动通过理由；也不强制所有作者换语言。确有不可移除成本，明确未达项、原因与可选替代，按实际完成范围交付，避免反复基准阻塞用户验收。

## 2. 先优化常驻路径

1. 原生事件推送/文件通知优先，日志只增量读取；无事件时保持休眠。低频存活检查共用一个低频timer，不给每个会话一个timer。
2. 将监控、起点状态留在最小常驻入口；安装/升级/导航/重型SDK按需加载，子进程请求后退出。长连接或起点状态需要常驻时保留，不能为省内存破坏协议语义。耗时helper使用独立执行队列，事件读取与推送继续工作；测试一项“慢helper期间仍收到事件”。
3. 用协议已支持的node/python3/executable入口作选择；先选满足预算的最简单方案。原生macOS包提供所支持架构与最低系统版本、可执行权限及签名校验；跨平台要求须分别构建，不宣称一个Mach-O能在Windows运行。
4. 不默认增加多工作端共享daemon或要求修改宿主。现协议每个monitor包各有进程；需要共享进程时先提出宿主契约变化，不能让插件擅自常驻后台或串发其他workEnd事件。
5. 客户端已有扩展运行时可用时，优先直接写小型、完整的白名单事件，避免为每条事件启动进程。没有扩展 API 的命令 Hook 保留最小原生/脚本入口，不为统一语言引入新常驻运行时。直接追加须验证并发完整性、文件权限、轮转及安静失败；同步 I/O 须说明慢文件系统代价，异步队列须有背压与退出排空语义。
6. Hook只记录白名单元数据和完整追加，安静失败且不阻断客户端。不要在每次Hook启动完整SDK、读整份转录或加载图像。

## 3. 正确性和内存边界

- 明确每批读取字节、最长完整行、会话/去重缓存边界、订阅数和请求并发。关闭/停止/切换代次清理对应状态。达到边界的行为写入README；有效事件不因优化被静默丢弃。
- UTF-8按**读取的字节数**推进offset；保存未完成字节到完整行再解码。截短/轮转重置半行；重建watch后继续监听后续追加，不只证明轮转后的第一条可读。
- 长stdin读取不能等满一个缓冲才处理已有JSON行。先用保持stdin打开的hello/inspect冒烟；EOF要排空已接收请求，再退出。
- 每个请求共用总时限，含运行时启动、子命令和收尾；普通3秒、维护15秒。按需helper不是预算豁免。SIGTERM/EOF/stop回收所属helper、watcher、timer与临时资源。
- 适配器包版本与原生Hook版本分别维护。仅常驻实现优化、Hook未变时，不要求重写客户端配置或重载已有会话。

## 4. 一次轻量证据与交付

按[基本验收性能分支](plugin-basic-acceptance.md#6-性能分开测量并保留原始样本)采样，不新增重型默认测试矩阵：

- 同机/运行时/输入/预热条件的前后对照；稳定空闲连续约20秒，原始CPU累计差分、RSS和可用物理内存数据。不把进程自启动平均CPU混作当前值。
- 单条正常事件延迟和一次超过读取批次的突发；缓存/进程生命周期用已有功能用例验证，不做无意义的数千次模型请求或重复压力测试。
- 两个工作端各测一次；共享机制只测一套。按需helper单列启动峰值和请求总耗时，不能只测常驻入口就声称全操作无Node成本。
- RSS含共享映射，不等于独占内存；不直接把RSS之和声称为系统实际新增RAM。区分宿主、适配器、helper/Hook、外部客户端、WindowServer；未测范围明确列出。
- 机制变化才重测。用户真实GUI验收在Char设置→性能开启采集，等待2秒观察对应行，关闭后停止采样并保留结果，需重新统计时使用重置按钮；不要求用户写命令或负责提供基本性能证据。

报告必须包含目标是否达到、前后数据、原始样本路径、能力/正确性检查、依赖/启动成本、已知边界及GUI更新/回退步骤。低占用不能以丢事件、隐藏子进程、放慢响应或削弱精度换取。
