# 用户验收交付规范

开发者完成[基本验收](plugin-basic-acceptance.md)后，交付测试包与操作说明，**用户自行使用客户端和 Char 验收**。这一阶段的默认任务是写清步骤，不是代替用户操作。

## 开发者先准备

- 最终包位于稳定、可访问的目录；每个包生产校验通过，版本与实际测试副本一致。解压后的目录可直接导入，不让用户构建。
- 列出依赖与客户端/Char 版本，说明“已存在”的查证结果。缺依赖时给 GUI 安装方式；无法用 GUI 准备时，明确具体缺口并提供可选择的协助，不能把一串命令交给用户或假装已就绪。
- 用 SDK/现有界面资料核对菜单名称及可用功能，按用户当前语言填好步骤。应用不同侧的加载方式可能不同：Desktop 正常菜单退出重开，CLI 新交互会话/客户端重载入口。没有已知交互式加载方式时明确阻碍，可请求仅为启动会话的协助授权；用户自己发送测试消息。
- 在工作区保存 `USER-ACCEPTANCE.md`。以下结构必须替换为具体软件、包绝对路径、菜单、支持类别、精度和等待时间；最终回复直接呈现全部可执行步骤，文件作为后续查阅，不以链接代替说明。

**只交说明时无需解锁、打开 Char/Finder、改设置、重启客户端或发模型请求。** 用户明确要求某项准备/代测时，执行该项并报告；历史允许安装不等于当前要求代测。用户已授权的动作不重复确认。

## 集成包：应交付的完整步骤

### 第一轮：导入与加载

1. 从 Char 状态栏或桌宠菜单打开**设置 → 插件 → 导入插件…**。文件选择框用“前往文件夹”（macOS ⌘⇧G）粘贴**实际包所在目录的绝对路径**，选整个 `.charintegration` 目录，不选 manifest。下载 ZIP 的先用系统界面解压。
2. v3 包说明会运行当前用户权限的代码，用户确认信任后导入。CLI/Desktop 双端分别导入，核对两行名称并打开开关；实际图标与 CLI 角标在第二轮气泡中检查。
3. 有 lifecycle 时在每行**扳手与螺丝刀菜单 → 安装**，再按本客户端的具体 GUI 加载方式保存工作并重载。没有 lifecycle 时给完整可交互安装方式；无需客户端扩展的跳过此项。
4. 在同一菜单**自检**，给出本包期望状态及解释。配置可用/ready 表示已检查配置；需要重载/reloadRequired 不等于失败，真正能收到事件在下一轮确认。配置包没有此菜单时只验证对应启停与能力图标。

附第一轮反馈栏：`各包导入___；图标/CLI角标___；安装___；自检状态/悬停说明___；客户端加载___`。

### 第二轮：每端最小使用

对每个交付端给出各自操作与预期，以下顺序按已声明能力删减，勿要求未支持类型：

1. 用户在新会话自然完成一轮普通、安全的短任务，自己选择并提交内容。说明这会使用其模型服务。若只需已有自然事件可直接等下一轮，不为验收制造危险审批或耗尽上下文。
2. 切到另一应用，等待本包支持的原生状态及 Char 当前过滤阈值加处理余量。阈值未查证时说明如何在设置查看，不能照抄开发机器数值。观察工作端身份、状态与 CLI 角标；不把未宣称的 question/failure 等作为必过项。
3. 点击气泡，写清本插件是准确会话导航还是应用级激活，及当前 Char 的提醒清除效果。应用级结果不要求选中对应 pane/聊天。
4. 从另一应用点击气泡再实体按 **Ctrl+B**，验证回到点击前的来源。默认保留首次起点，有旧起点时先在桌宠菜单**结束回城**；用户选择最近起点/关闭记录时按其配置给预期。插件没有 origin 也可由宿主应用级回城。
5. tmux/不同终端/多屏仅在用户实际使用且包声明适配时分列，不能把一端成功概括为全部环境成功。偶尔发生的审批/子会话等按自然使用补验，无原生证据仍列待验证。

附逐端反馈表：`环境 | 自然事件/气泡 | 图标/状态 | 点击去向/清除 | Ctrl+B | 失败步骤/时间`。

### 第三轮：热维护与恢复

1. 关闭该包开关后，新活动不产生该工作端的新提醒；其他包继续正常。重新启用后用新活动测试，不期待补播停用期间历史。
2. 保持 Char 运行，**同 ID 重导入完整集成包**，应只有一个条目且启停意图保留。需要原生扩展升级时用菜单**更新集成**并按客户端方式重载、自检；准确旧锚点失效是预期。同版本重导入只证明替换流程，不证明跨版本迁移。
3. 垃圾桶删除时解释**仅删除插件**与**卸载集成并删除**。共享双端先卸载一端，剩余端继续可用，再按需卸载最后一端；保留备份/无关文件属于预期。
4. 需要恢复时重新导入→安装/加载→自检。客户端持有旧快照时正常重启使其回收；不要求用户清空缓存、改整个目录权限或刷新官方市场。

附反馈栏：`停用/恢复___；重导入/更新___；删除一端后另一端___；全部卸载/恢复___`。第三轮说明完整交付，用户可在基本使用正常后再做。

## 外观包：应交付的完整步骤

1. 给包绝对路径及预览。解压后从**设置 → 桌宠与动效（Appearance）→ 导入形象…**选整个 `.charpet` 目录；导入会立即选中。含形象脚本时出现“启用形象脚本？”确认；纯图片包无此步骤，不需客户端安装菜单。
2. 桌面与四边分别看探出、落位idle、点击反馈、回城和收回；角色朝向与裁切一致。回城先建立有效起点再按Ctrl+B。调整36/48/88pt检查轮廓/透明/身份与接缝；独立每边资源按作者说明核对。
3. 本包声明了跟随时，在宠物/气泡附近移动并停住鼠标，确认眼睛与转头方向、无双影；声明主题时切换每个主题，检查宠物、气泡、软件图标和重启保留。音效开启/静音、重复触发冷却按本包实际事件测试；不要求用户触发未支持的Agent状态。
4. 只测声明的交互/布局：宠物点击、气泡点击、hover/drag动作、吸边、碰撞、焦点跟随、回城策略、距离与折叠/滚动。关闭“使用形象行为偏好”应回到用户原偏好；脚本/bindings仍启用。描述本包与默认行为的差别，用户无需自行猜测。
5. 有多屏时切换工作焦点；手动切Space，检查宠物与气泡同步。系统Reduce Motion开启后检查静态/减弱运动。没有设备或权限的项标为未测试。
6. 在Finder“应用程序”中看Char图标，再看Launchpad（当前系统提供时）；应随选中形象/主题更新，设置显示“安装图标已同步”。失败时保留原安装并显示原因，该项记为未通过或受环境阻碍，不以运行图标正常代替安装图标通过；若辅助功能变为未授权，在系统设置中只移除并重新添加 `/Applications/Char.app`，不要重置全部隐私权限。系统缓存呈现尚未确认不能记通过。
7. 重启Char检查形象、主题和行为选择保留。删除当前包恢复默认宠物和图标，旧脚本/音效停止。**同ID更新先删除旧包再导入新包**；保存旧包以便回退，不套用集成包热替换步骤。

反馈表：`桌面/四边 | 跟随/动作 | 主题/气泡 | 音效/静音 | 交互/布局 | 多屏/Space | Finder/Launchpad | 重启/删除 | 问题截图/时间`。未声明的列写不适用。

## 完成声明与失败反馈

最终回复明确三件事：

1. **开发及基本验收完成**：包与源码链接、版本、已执行检查和真实条件，图标来源、能力/信号/精度与已知缺口。
2. **待用户验收**：上述完整填好步骤与简短反馈表；已获用户自然使用证据时逐项标明，不把未知补成通过。
3. **失败与恢复**：用户停在出错步骤，提供端/环境、时间、状态图标悬停说明或截图。去敏诊断由开发者按反馈准备，用户无需运行日志命令；保存现场，不扩大清理范围。

若反馈“只有图标不对”，只修资源、重建并交付重导入步骤；不会自动重装客户端或重复整套验收。针对失败重测受影响路径。只有适用的原生事件与 Char 产品链路有证据才更新正式支持声明；用户未测不阻塞开发交付，也不是基本检查失败。
