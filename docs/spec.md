# Cross-Harness Attention Router（char）首版规格

## Problem Statement

使用者同时在不同官方 harness 中运行多个 Agent，包括直接在 Warp 或 Warp + tmux 中运行的 Claude Code TUI、Codex CLI、pi，以及 Codex Desktop、DeepSeek Harness Desktop 和 Kimi Code。某个会话提问、等待审批、结束一轮工作或遇到故障时，使用者可能正在 Tabbit、微信、VS Code、Warp 或另一块屏幕上工作，无法及时发现停顿；即使发现，也要花时间找到正确会话。处理完 Agent 后，再找回打断前的界面又增加一次切换成本。

现有跨 Agent 监视工具已经能汇总部分状态，但粗粒度的 `working/waiting` 不足以说明停顿原因，也不能保证一击进入原会话并返回最初界面。char 要解决的是“谁需要我、为什么、怎样马上过去、怎样回到我原来的工作位置”。

## Solution

char 是仅在本机运行的 macOS 旁路观察器，不接管原生会话。它从各工作端的本地会话记录和可选的官方 Hook 获取信号，为持续达到全局过滤阈值的后台停顿生成注意力项。常驻桌宠旁按工作端显示图形气泡：原因类别、未查看数量和 Agent 身份一眼可见；单击气泡直接尝试进入对应原生会话。精准跳转失败时，char 至少切到工作端最近位置，以图形表示降级，并保持注意力项未查看。

首次通过气泡离开当前界面时，char 尽可能捕获准确返回锚点并进入 Hold；微信首版只保存明确标记为降级的应用实例。连续访问其他 Agent 不覆盖这个锚点；点击桌宠回到仍存在的具体标签或编辑器，或以图形降级返回微信应用最近位置。Warp 来源仅能识别到应用而不能准确捕获 pane 时不建立 Hold。手动回到锚点、主动结束、来源关闭、char 重启或宽限期到期会结束 Hold。桌宠在所有 Space 和全屏应用中可见，跟随当前操作的屏幕，以短促、可中断的传送动效提示位置变化。

## User Stories

1. 作为同时运行多个 Agent 的开发者，我希望继续从各自的官方 harness 启动和使用 Agent，以便保持原有工作方式。
2. 作为 Mac 用户，我希望 char 在登录后默认自动启动，以便工作开始时便能观察新停顿。
3. 作为 Mac 用户，我希望可以关闭登录自动启动，以便自行控制 char 的运行时间。
4. 作为本机 Claude Code TUI 用户，我希望 char 观察我的原生会话，以便停顿时收到提醒。
5. 作为本机 Codex CLI 用户，我希望 char 观察我的原生会话，以便停顿时收到提醒。
6. 作为本机 Codex Desktop 用户，我希望 char 观察应用中的本机聊天，以便停顿时收到提醒。
7. 作为使用 Warp + tmux 的开发者，我希望早于 char 启动的 CLI 会话在之后停下时仍能被观察并提醒，以便不必重启 Agent。
8. 作为不希望被旧事件淹没的用户，我希望 char 启动时不回放先前的等待，以便只处理运行期间新发生的事件。
9. 作为合上 Mac 盖子的用户，我希望唤醒后看见睡眠期间发生且仍有效的新注意力项，以便不漏掉仍需关注的会话。
10. 作为并行工作的用户，我希望当前准确会话已获得焦点时不弹气泡，以便不被已经看见的状态打断。
11. 作为在 Warp 分屏工作的用户，我希望另一个可见但未获得焦点的 Agent pane 停下时仍弹气泡，以便注意到它在等待。
12. 作为并行工作的用户，我希望不足过滤阈值的暂态停顿不提醒，以便减少误报。
13. 作为并行工作的用户，我希望能全局调整过滤阈值，并以 10 秒为默认值，以便按自己的工作节奏平衡漏报和误报。
14. 作为并行工作的用户，我希望 Agent 向我提问时出现对应原因的气泡，以便知道需要回答。
15. 作为并行工作的用户，我希望 Agent 等待权限审批时出现对应原因的气泡，以便知道需要批准或拒绝。
16. 作为并行工作的用户，我希望后台会话给出本轮最终回复时出现气泡，以便及时检查结果，而不把它误认为整项任务完成。
17. 作为并行工作的用户，我希望 Agent 异常退出时出现气泡，以便及时处理失败。
18. 作为并行工作的用户，我希望限流或上下文耗尽时出现相应气泡，以便知道继续工作受阻。
19. 作为并行工作的用户，我希望停顿已确认但原因不明时仍看到未分类停顿气泡，以便少漏掉需要关注的会话。
20. 作为并行工作的用户，我希望每个原生会话只有一条当前注意力项，以便相同会话的连续变化不会堆成一串通知。
21. 作为并行工作的用户，我希望气泡出现后 Agent 自行恢复时注意力项仍保留，并显示已过去标记，以便仍能查看这次停顿而不会被误导为当前阻塞。
22. 作为并行工作的用户，我希望桌宠旁每种工作端只显示一个聚合气泡，以便多个会话同时停下时桌面仍整洁。
23. 作为同时使用 Codex CLI 与 Codex Desktop 的用户，我希望它们显示为不同工作端气泡，以便跳转目标明确。
24. 作为并行工作的用户，我希望气泡显示当前最紧急的原因图形和未查看数量，以便一眼判断哪里需要关注。
25. 作为不想阅读悬浮文字的用户，我希望日常气泡不展示任意提问或命令原文，以便界面保持轻量。
26. 作为需要理解图形语义的用户，我希望能在设置中查看图形图例，以便分辨原因、已恢复项和降级反馈。
27. 作为并行工作的用户，我希望运行中的会话只折成计数，以便主要视觉空间留给注意力项。
28. 作为被多个会话同时请求的用户，我希望当前仍在等待的项先于已恢复项、提问和审批先于异常与限制、轮次结束排最后，以便每次点击先到更急的会话。
29. 作为面对同级注意力项的用户，我希望等待最久的会话先被访问，以便没有会话长期被排在后面。
30. 作为收到气泡的用户，我希望单击气泡立即跳转，而无需先打开队列，以便减少切换步骤。
31. 作为 Claude Code TUI 用户，我希望点击气泡至少进入 Warp 最近位置并看到图形降级反馈，以便继续手动寻找原会话且不误以为已准确到达。
32. 作为 Codex CLI 用户，我希望点击气泡至少进入 Warp 最近位置并看到图形降级反馈，以便继续手动寻找原会话且不误以为已准确到达。
33. 作为 Codex Desktop 用户，我希望点击气泡进入 Codex 最近位置并看到图形降级反馈，以便手动找到目标聊天且不误以为已准确到达。
34. 作为 Warp 中 Agent 的用户，我希望原 Warp 标签已关闭但 tmux pane 仍在时，点击气泡仍打开 Warp 最近位置并保留未查看项，以便知道需要手动接回原会话。
35. 作为遭遇精准跳转失败的用户，我希望 char 至少打开对应工作端最近位置，并用图形标明降级，以便知道跳转并未到达目标。
36. 作为遭遇降级跳转的用户，我希望注意力项继续保持未查看，以便它不会因为只打开了应用而消失。
37. 作为手动找到原会话的用户，我希望 char 在准确会话获得焦点后清除对应注意力项，以便队列反映我已查看的内容。
38. 作为暂时不想处理当前会话的用户，我希望右键气泡只忽略当前排首的一项，以便同工作端其他会话仍被提醒。
39. 作为被多个停顿同时打断的用户，我希望短时间内的提醒合并响一次，以便提示音不会连续轰炸。
40. 作为需要控制声音的用户，我希望提示音默认开启、可以静音并选择一个本地音频文件，以便提醒符合个人环境。
41. 作为从 Tabbit 离开的用户，我希望首次点气泡时记住原标签，以便处理 Agent 后回到仍存在的同一标签，即使它被移到别的窗口或显示了新网页。
42. 作为从微信离开的用户，我希望只能捕获应用位置时看到图形降级返回，并知道没有准确返回原聊天。
43. 作为从 VS Code 离开的用户，我希望桌宠返回仍存在的原编辑器或终端标签，以便继续被打断前的工作。
44. 作为从 Warp 离开的用户，我希望 char 无法准确捕获原 pane 时不显示 Hold，以便桌宠不会承诺无法验证的原处返回。
45. 作为切往多个 Agent 的用户，我希望 Hold 始终保留第一次点气泡前的返回锚点，以便点桌宠直接回最初界面。
46. 作为无法捕获准确来源的用户，我希望气泡仍可跳转 Agent、桌宠不进入 Hold，以便不制造错误的返回承诺。
47. 作为只被带到工作端最近位置的用户，我希望桌宠仍能带我回准确来源，以便降级跳转也不会让我迷路。
48. 作为完成 Agent 处理的用户，我希望左键桌宠返回原来仍存在的来源界面，不重新打开其内容，以便回到原有上下文。
49. 作为自行切回来源的用户，我希望 Hold 静默结束，以便桌宠不再显示多余的返回提示。
50. 作为改变计划的用户，我希望右键桌宠能主动结束 Hold 且留在当前位置，以便放弃这次往返。
51. 作为手动转去其他页面的用户，我希望 Hold 暂时仍保留最初来源，以便短时间内仍可点桌宠返回。
52. 作为已经转去做别的事的用户，我希望离开 Agent 后的宽限期累计达到默认五分钟时 Hold 静默结束，以便忘记返回时不会长期挂着旧锚点。
53. 作为重新回到 Agent 的用户，我希望 Hold 宽限期暂停并在再次离开时继续，以便处理 Agent 的时间不侵蚀返回机会。
54. 作为需要不同节奏的用户，我希望可以调整 Hold 宽限期，以便自动结束符合自己的习惯。
55. 作为关闭来源界面的用户，我希望 Hold 随即失效，以便桌宠不会指向已不存在的位置。
56. 作为重新启动 char 的用户，我希望旧 Hold 不被恢复，以便不会看到无法保证仍有效的返回锚点。
57. 作为来源是 Warp pane 的用户，我希望若未来的准确捕获路径失效，char 只回到 Warp 最近位置、显示图形降级反馈并结束 Hold，以便知道未回到原 pane。
58. 作为多屏用户，我希望唯一的桌宠跟随当前操作窗口所在屏幕，并记住各屏位置，以便提醒始终在眼前。
59. 作为全屏和多 Space 用户，我希望桌宠与气泡仍可见，以便不因工作界面变化错过提醒。
60. 作为频繁切屏的用户，我希望桌宠用快速传送动效表达换屏且不延迟点击，以便获得位置感而不影响工作。
61. 作为启用系统减少动态效果的用户，我希望桌宠以简化淡入淡出替代位移动效，以便提醒仍清晰而舒适。
62. 作为当前没有 Hold 的用户，我希望左键桌宠只有轻微视觉回应，以便不会意外打开面板或改变焦点。
63. 作为关注工作隐私的用户，我希望会话原文和状态只在本机处理，不上传或同步，以便工作内容不离开这台 Mac。
64. 作为处于 Hold 的用户，我希望桌宠显示返回锚点所属应用的图标，以便不读文字也能知道点击后会回到哪里。
65. 作为需要调整提醒的用户，我希望右键桌宠即可进入设置或静音，以便直接控制 char 的行为。
66. 作为需要准确跳转的用户，我希望能通过一次性终端集成和 macOS 辅助功能授权启用定位，以便继续使用现有的原生会话。

67. 作为使用 DeepSeek Harness Desktop、Kimi Code 或 pi 的用户，我希望原生停顿也能产生各自工作端气泡，以便沿用同一注意力流程。
68. 作为直接在 Warp 中运行 Agent 的用户，我希望无需 tmux 也能观察 Claude Code、Codex CLI 和 pi，以便保持启动习惯。
69. 作为处理完 Agent 的用户，我希望按 Ctrl+B 执行“回城”，以便回到最初来源。

## Implementation Decisions

- 首版仅面向 macOS 单机、本机原生会话，支持 Claude Code TUI、Codex CLI、Codex Desktop、DeepSeek Harness Desktop、Kimi CLI、Kimi Code App 和 pi。CLI 直接在本机 Warp 或 Warp + tmux 中运行；tmux 不是观察的前置条件。char 是旁路观察器，可选用 harness 官方 Hook，但不拥有 Agent 的启动或运行控制权。
- char 拥有工作端适配层、统一观察事件、注意力状态、跳转与返回锚点的定义。AgentHUD 可作为辅助信号，不是必需依赖或核心 fork。
- 2026-10-04 使用者批准首版按已确认的原生信号交付，缺失类别另行跟踪。当前矩阵见 `docs/observation-integration.md` 与 `docs/new-agent-observation.md`：Codex CLI/Desktop 的 failure、rate limit、context exhaustion，Claude 的 context exhaustion，以及 pi 的独立 approval、rate limit、context exhaustion 不作为首版已提供能力。pi 的普通 blocking UI 属于 question，不能当作权限审批。#5 跟踪这些缺口；没有停顿信号时不产生提醒。
- 观察事件至少要保留工作端、原生会话身份、发生时间、停顿类别及用于定位的目标信息；缺少可靠类别时使用未分类停顿。提问、审批、轮次结束、异常、限流、上下文耗尽是独立类别；轮次结束只表示当前一轮最终回复。
- 注意力状态由统一的高层流程管理：先检查准确会话是否已获得焦点，再对后台停顿应用全局可调过滤阈值，默认 10 秒。char 启动前已存在的会话可被监视，但启动前已经发生的等待不回放；睡眠期间发生且醒来仍有效的新事件需恢复。
- 每个原生会话最多保留一个当前注意力项；气泡出现后 Agent 自行恢复不会自动清除该项，而是增加已过去标记。只有准确会话获得焦点或用户忽略当前项才清除它。
- 注意力项按工作端聚合，Codex CLI 与 Codex Desktop、Kimi CLI 与 Kimi Code App 分开。聚合气泡显示当前首项的原因图形及数量；当前仍等待的项优先于已恢复项，提问与审批优先于异常及资源限制，轮次结束最后，同级按等待时长排序。
- 气泡左键直达排首的原生会话，右键忽略该项；不设置先展开队列的必经步骤。运行中会话只显示计数，任意提问及命令原文不进入日常气泡。
- 首版所有工作端均采用应用级跳转：CLI（含 pi）激活 Warp 最近位置，桌面工作端激活各自应用最近位置，显示纯图形降级反馈，注意力项保持未查看。仅激活应用不能证明准确会话已查看，不能据此压下提醒或清除注意力项。准确 pane 与聊天跳转另行跟踪。
- Warp + tmux 的准确 pane 聚焦与原 Warp 标签关闭后的自动重接延期，直到有可运行且经实机验证的路径。一次性终端集成或 macOS 辅助功能授权可用于未来的准确定位，但仅有权限或 tmux pane ID 不构成准确聚焦证据；这些集成不改变原生会话的启动归属。
- 返回锚点是首次点击气泡前的准确来源界面。目标工作端发生切换后进入 Hold；后续气泡点击不覆盖锚点。来源捕获失败时仍可跳转，但不建立 Hold。Tabbit、VS Code 通过可用集成捕获准确来源；捕获失败时不建立 Hold。微信只捕获仍存活的应用实例作为降级来源，Hold 显示降级标记，点击桌宠仅激活原应用最近位置并结束 Hold，不宣称返回原聊天。Warp 来源若只能识别到应用、不知道准确 pane，不建立 Hold；Warp pane 的准确返回延期。
- 返回最初来源的行为称为“回城”。Hold 中点击桌宠或按 Ctrl+B 执行同一回城动作；无 Hold 时释放快捷键，不影响终端通常的 Ctrl+B。快捷键注册冲突在设置中显示。回城只聚焦原来仍存在的标签、聊天或编辑器，不重建其内容；手动回到原界面会静默结束 Hold。来源关闭、char 重启、主动结束或宽限期到期也结束 Hold。微信应用级返回只激活原应用并以图形标记降级后结束 Hold。未来若能准确捕获 Warp pane 而返回时失效，可只激活 Warp 最近位置，图形标记降级并结束 Hold。
- Hold 中桌宠显示返回锚点所属应用的图标。宽限期仅在用户手动离开 Agent 到非锚点界面后计时，默认累计五分钟且可调整；回到 Agent 时暂停。到期来源图标快速淡出，不发声。
- 一个桌宠跨所有 Space、全屏应用与显示器跟随当前操作窗口，记住各显示器的位置；鼠标仅越过屏幕边界不触发传送。动效提案约 180 毫秒、可中断且不阻塞气泡，系统减少动态效果时简化。具体原创形象由原型探索。
- 图形系统需要区分工作端、原因类别、聚合数量、已恢复项、Hold 来源和降级结果。日常反馈不显示可见文字；设置中提供图形图例和提示音、过滤阈值、宽限期、自启动控制。
- 桌宠右键菜单提供设置、静音和主动结束 Hold；普通状态左键只给轻微视觉回应，Hold 中左键执行返回。
- 提示音默认开启，短时间多事件合并播放一次；用户可以静音并选用一个本地音频文件。会话内容和状态仅在本机处理，不上传、不跨设备同步。
- 子 Agent 不单独产生注意力项；只有父原生会话需要用户关注时才提醒。

## Testing Decisions

- 仓库已有可执行 Swift 契约检查、Hook 安装器检查、VS Code 集成检查及原生应用 smoke。继续复用最高层验收接缝：在可控的 harness 事件、桌面焦点、时钟和用户输入下运行 char，观察气泡、提示音、窗口焦点与 Hold 的外部行为。通过这一个接缝覆盖排序、过滤、降级、清除和返回，而不是为每个内部状态函数建镜像测试。
- 测试只对外部可观察结果下断言：某类事件何时产生气泡、哪个会话被切到、注意力项是否仍未查看、桌宠是否能回准确来源、声音是否合并、Hold 何时结束。避免断言适配器内部类名、缓存结构或动画实现方式。
- 工作端适配器需按当前批准的能力矩阵，用真实本机会话与官方 Hook 的代表性输入验证已确认类别及未分类停顿；已确认停顿但原因不明时使用未分类路径，缺少停顿信号时不能假报未分类。此类契约检查用于弥补统一验收环境无法复现的 harness 差异。
- macOS 实机验收需覆盖：启动前已存在、启动后才停顿的 tmux 会话都能被观察；点击 CLI 气泡只激活 Warp 最近位置、以图形标明降级且不清除注意力项；原 Warp 标签关闭而 tmux pane 仍在时也不宣称已接回；Codex Desktop 应用级跳转、图形降级与未查看保留。准确目标已获焦点和分屏可见但未获焦点两种情况仍需在具备准确焦点信号的工作端验证；Warp 无法判断时不得假定准确焦点。
- 返回验收需覆盖 Tabbit 原标签跨窗口移动及页面变化、VS Code 原编辑器或终端标签的可用集成，以及微信应用级降级返回；Warp 来源只捕获到应用时不建立 Hold。连续访问多个 Agent、来源内切换到另一聊天或标签、手动回来源、来源关闭、来源不可捕获、char 重启与降级返回都应有明确结果。
- Hold 验收需检查桌宠是否显示最初来源应用的图标，连续访问 Agent 时图标是否保持，以及主动结束或宽限期到期后是否清除。桌宠右键的设置、静音和结束 Hold 也应通过实际用户输入验证。
- 时间验收需覆盖阈值前自行恢复、阈值后自行恢复、睡眠期间新停顿、多个事件短时间到来，以及 Hold 宽限期在 Agent 与非 Agent 界面间的累计、暂停、静默到期。
- 桌面体验需在多显示器、多个 Space、全屏应用和系统减少动态效果模式下实测。跨屏传送不能阻塞气泡点击；纯图形原因、已过去和降级反馈需通过实际原型理解测试，而非只检查图标是否绘制。
- 本地处理约束需验证 char 在正常监视、提醒和返回流程中不上传会话内容或状态。默认自启动、静音、自定义音频文件、过滤阈值和宽限期设置需经过关闭再启动后的行为验收。
- 当前已有的检查和实机报告分别证明各自路径；注入事件不能替代真实 harness 生命周期证据。Warp 精确 pane 定位、Codex Desktop 精确聊天与微信精确聊天返回已从首版验收中延期。首版以应用级降级作为工作端跳转；Tabbit 与 VS Code 的准确返回仅在集成能捕获并验证仍存在的准确来源时启用，否则遵循不建立 Hold 的路径。完整产品验收在实现中使用统一接缝并记录可运行的实机证据。

## Out of Scope

- 首版未确认的原生停顿类别（上列 Codex、Claude、pi 缺口），继续由 #5 跟踪；不能由任意错误文字、空闲或 token 计数猜测。

- Codex Desktop 准确聊天跳转和微信准确聊天返回；首版只提供应用级图形降级，精准能力另行跟踪。

- 在 Linux、Windows 或多台机器之间监视 Agent；监视 SSH 远端、Codex 云端及远程任务。
- 由 char 启动、托管、重启或管理 Agent 的 PTY、tmux 生命周期；在气泡里直接回复问题、批准权限或发送命令。
- 在当前 Warp Stable 构建中准确聚焦原 pane、自动重接已关闭 Warp 标签后仍存在的 tmux pane，以及将 Warp pane 作为首版准确返回锚点；这些能力需另行验证后再纳入。
- 启动时补回历史等待、回放旧轮次或持久化恢复上一次 Hold。
- 将每个子 Agent 独立显示为气泡；完整活动日志、用量仪表盘、项目管理、PR 工作流。
- 在气泡或降级反馈中显示任意问题原文、命令正文或可见文字说明；按原因分别配置提示音。
- 关闭的返回来源自动重建；向外部服务上传会话原文或状态；跨设备同步和遥测。
- 预先锁定桌宠物种、最终图形、动效曲线或某一具体 UI 框架；这些需由原型和实机验证确定。

## Further Notes

- 本规格记录已讨论的用户行为，准确窗口或聊天定位、图形语义和动效仍需运行时验证。若验证发现某条首版验收路径不可实现，应先调整该路径的产品约束，再开始完整实现。
- [AgentHUD 的实时事件流](https://github.com/neochoon/agenthud/blob/main/FEATURES.md#follow)可提供粗粒度跨工作端信号；它本身没有覆盖本规格的完整原因与窗口定位，因此被列为可选辅助源。
- Warp 的公开 URI 文档主要描述创建新窗口或标签；其仓库另有精确控制窗口、标签和 pane 的[设计文档](https://github.com/warpdotdev/warp/blob/master/specs/warp-control-cli/PRODUCT.md)。当前用户安装的 Warp Stable 没有可用的 `warpctrl` 包装命令、Scripting 开关或本地控制端点，设计文档不能替代这条实机路径。


## 2026-10-04 插件与视觉扩展（Issue #14）

来源和工作端配置成为可导入、即时启停、删除、显式恢复的配置插件。内置原生协议仍遵守已批准的信号矩阵；插件配置所属应用和图标，应用级来源保存同一存活实例，不宣称精确返回页面。停用工作端立即移除其注意力项和运行计数，重新启用从当前时刻观察；停用当前来源结束 Hold。

默认形象采用参考图的奶油色粗圆角方块、深色描边、竖线眼睛和小脚。桌面放置使用圆环气泡，四边放置探出部分身体并把气泡排列到屏幕内侧。气泡固定 52 pt，六个轨道位置；超出时最后一个位置显示最多三个可访问小气泡，滚轮或无障碍下一组动作循环访问全部工作端。气泡和桌宠使用柔和形变；系统 Reduce Motion 停止持续动作并缩短过场。

跨屏移动分为退出和进入，桌面缩小消失，边缘缩回；切换 Space 选择桌宠持续存在。回城动作立即派发应用激活并同时给予弹性反馈，不增加人为等待。macOS 整屏 Space 的切换曲线由系统控制，本实现不使用私有 API 或修改系统设置。

自定义形象使用版本化 `.charpet` 七动画 RGBA PNG 标准，导入验证后本地安装，选择持久化；删除所选形象自动恢复默认。标准与可导入示例见 `docs/pet-skin-format.md`、`Resources/Skins/example.charpet`。配置插件标准与来源示例见 `docs/integration-plugin-format.md`、`Resources/Integrations/safari.charintegration`。

2026-10-04 使用者确认本阶段按上述桌宠反馈和跨屏动画范围交付，整屏 Space 动画另行由 [#15](https://github.com/CheeseFox259/Char/issues/15) 跟踪。该延期不改变其它已记录的实机未运行项。

## 2026-10-04 使用反馈后的紧凑交互修正

默认形象移除附肢，默认 48 pt、设置可调 36–88 pt。气泡固定 44 pt，紧凑轨道，透明玻璃外壳内使用所属 Agent 图标；CLI 增加小终端角标。眼睛跟随气泡附近指针，悬停产生轻微抬升/放大和亮边；边缘姿态保留内向眼睛与倾斜。

所有屏幕共享放置方式、大小及归一化位置，旧的每屏状态不再恢复。默认跨屏退出/进入为 90/150 ms；显示器检测从观察轮询独立，150 ms 检查并辅以应用激活通知，真实延迟另做计时。自定义形象仍播放其完整声明动画。

只有气泡折叠时才可循环滚动。带手势阶段的触摸板首步阈值 6 pt，连续步骤 36 pt，180 ms 节流并忽略惯性；无阶段的精细鼠标事件束只接受起始一步，65 ms 无输入、方向反转或尾部重新出现明显峰值时开始新束，避免一个刻度的衰减尾部再次换位。普通离散鼠标保持直接步进与节流。

手动 Space 切换采用 700 ms、零初始速度的弹性重现；桌宠、主气泡及折叠小气泡共享收放与透明度，闲置、点击、回城和跨屏也联动。窗口保持不透明，只改变内容图层，减少遮挡通知反馈造成的闪烁。保持可见的内容不因延迟通知重播；实际隐藏后的出现只播放一次。跨屏过渡本身提供收放，已准备的隐藏周期可等待迁移完成再出现。系统 Reduce Motion 使用较短淡入。整屏系统曲线仍由 #15 跟踪。

日常气泡用一个胶囊合并状态/数量：需关注、发生问题、轮次结束；已恢复项用淡色，只有运行中时显示一个运行数量胶囊。精确停顿类别不改变，未分类停顿不伪装成已确认提问，轮次结束不宣称任务完成。新增状态栏图标与设置、显示桌宠、回城、静音、退出菜单；菜单只含操作，不显示分类统计。设置窗口仅保留关闭按钮，不提供最小化、缩放或全屏。性能开销和优化计划见 `docs/companion-performance-2026-10-04.md`。
