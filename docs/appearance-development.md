# 外观包开发指南

外观插件在当前版本叫 **形象包**，后缀 .charpet；只包含清单和图片。它改变桌宠形象与七种动作，不替换气泡布局、窗口策略、回城逻辑或默认形象的程序化眼睛跟随。

## 开发流程

1. 选择透明画布和角色。128×128通常够用；坐标锚点以画布左上为原点，默认中心(0.5,0.5)。
2. 制作七组动画：idle、press、return、depart、arrive、edgePeek、edgeHide。路径在包内，所有帧为相同画布的单图8-bit RGBA PNG。
3. 编写 manifest.json，以固定顺序列出帧，不依赖文件名排序。FPS有限且在1–60；每组2–120帧，总引用不超过480。
4. 用生产校验器检查，再用设置导入并检查实际桌面/边缘动作。程序导入仅安装包；设置中的“导入形象”在安装后立即选中。
5. 分发目录或压缩目录。用户下载压缩包后先解压，再选择 .charpet 目录；当前没有直接ZIP导入。

~~~sh
swift run char-package-check skin Resources/Skins/example.charpet
bash scripts/build-app.sh
~~~

完整144帧参考包：[example.charpet](../Resources/Skins/example.charpet)。详细规范：[pet-skin-format.md](pet-skin-format.md)。[通用开发指令](../Resources/Skins/AGENTS.md)提供制作、预算、预览和验收流程；角色设计及帧数量按当前任务决定。

## 动画与布局合同

| 动作 | 播放/触发 | 制作建议 |
| --- | --- | --- |
| idle | 循环 | 呼吸、压缩/拉伸、回弹、轻倾和眨眼；首尾姿态衔接 |
| press | 一次 | 短压缩反馈，留出弹性回弹 |
| return | 一次 | 回城触发反馈；不要假装控制系统整屏转场 |
| depart / arrive | 跨屏桌面迁移 | 消失端收小/透明，出现端从小/透明展开 |
| edgeHide / edgePeek | 边缘迁移 | 缩回/探出，App同时施加边缘位置和裁切 |

App按最大画布边缩放到当前36–88 pt桌宠尺寸，非正方形会保持比例，anchor放到保存的位置。预览不能代表物理边缘裁切，需要实际检查五种放置。非 idle 动作播放最后一帧后保持，交互结束回到idle；迁移动作使用自定义动作时长分阶段。较长反馈会改变交互观感，建议0.2–0.7秒短动作。

形象包没有眼睛骨骼、程序化瞳孔或指针方向通道。默认方块的鼠标跟随不能自动迁移到位图角色；不要在交付中声称自定义眼睛会跟随。支持这个能力需要另行扩展清单和渲染器。

## 导出与内存预算

- 每帧32–512像素，必须PNG IHDR bit depth8/color type6（RGBA）；RGB、索引色、灰度、16bit、APNG均不接受。
- 每帧≤4 MiB，manifest≤64 KiB，整包≤32 MiB，目录项≤600，唯一帧的像素总数≤16,777,216。包内不能留未引用PNG、预览视频、README、脚本或符号链接。
- 理论解码像素内存约唯一帧数×宽×高×4字节，还包括NSImage/CGImage/缓存开销。压缩包大小不能代表常驻内存；先复用相同静止帧，再提高分辨率/FPS。
- 144张128×128唯一帧约9 MiB裸RGBA像素；144张512×512会超出像素预算，校验拒绝。
- 外部生成/绘制的精灵图必须切成严格等大小帧并导出RGBA。自动颜色模式压缩成RGB/调色板时，需要重新转为RGBA导出。

## 验收与回退

~~~sh
swift run char-package-check skin /absolute/path/moon-square.charpet
~~~

0表示包符合生产格式；1表示无效；2表示命令用法错误。随后从设置导入，检查预览、idle首尾、press/return、桌面/四边、迁移、36/48/88 pt、重启选择、删除回退及系统Reduce Motion。没有多屏或系统权限的项目标为未运行，不能将打包校验当作这些行为通过。

导入验证完成后复制、再次验证、同目录重命名发布；不执行包中代码。重名ID拒绝导入，更新需先删除旧自定义包。删除当前包回到内置char.default；内置形象不能删除。用户数据在 ~/Library/Application Support/Char/skins，开发检查用临时目录，不直接修改该位置。

性能复测按[性能报告](companion-performance-2026-10-04.md)的20秒CPU/RSS方法，记录包ID、分辨率、唯一帧数、FPS、可见气泡和设置状态。不得承诺“60FPS必然低功耗”；以实际解码与动画场景样本为准。
