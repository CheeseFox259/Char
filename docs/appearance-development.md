# 外观包开发指南

外观插件称为 **形象包**，后缀 .charpet。形象包可提供独立边缘姿态、原生眼睛/头部跟随、主题、气泡样式、音效、Char事件脚本、交互和布局偏好，并自动同步安装图标。先读本文制作流程，再按[完整 API](appearance-api.md)使用本次所需能力。

## 开发流程

1. 确定素材处理方式、透明画布和角色，先完成基准形象与短 idle；按下节检查后扩展。坐标锚点以画布左上为原点，默认中心(0.5,0.5)。分辨率按最大显示点数×屏幕倍率及像素预算选择，128×128适合小尺寸；需要88pt@2x清晰度时可用192或256，并减少重复资源。
2. 使用 schemaVersion 2；只声明需求所需的功能和资源，纯图片形象可省略 features。制作七组动画：idle、press、return、depart、arrive、edgePeek、edgeHide。路径在包内，所有帧为相同画布的单图8-bit RGBA PNG。
3. 为同一角色制作静态软件图标，导出独立的128/256/512/1024正方形8-bit RGBA PNG（推荐1024），用可选 appIcon 路径引用。旧包无此字段时按最后的 edgePeek 帧生成右边缘图标。包像素预算包括图标。
4. 编写 manifest.json，以固定顺序列出帧，不依赖文件名排序。FPS在1–60；每组2–120帧。总帧引用≤2048，唯一PNG仍受像素预算限制。
5. 用生产校验器检查最终包，实际观看七组完整离线预览与 idle 循环；按[基本验收的外观分支](plugin-basic-acceptance.md#7-外观包数据完整动画与预算)记录透明度、anchor、图标与预算。真实 Char 组合行为默认交给用户验收。程序导入仅安装包；设置中的“导入形象”在安装后立即选中。
6. 分发目录或压缩目录。用户下载压缩包后先解压，再选择 .charpet 目录；当前没有直接ZIP导入。

~~~sh
swift run --package-path /absolute/path/Char char-package-check skin /absolute/path/your.charpet
~~~

完整144帧参考包：[example.charpet](../Resources/Skins/example.charpet)。详细规范：[pet-skin-format.md](pet-skin-format.md)。[通用开发指令](../examples/appearance/AGENTS.md)提供制作、预算、预览和验收流程；角色设计及帧数量按当前任务决定。

## 素材、工具与制作路径

- 先检查当前环境或宿主提供的图像运行时及已安装依赖。确实缺少Pillow/numpy等工具时再建立隔离环境；安装先做单次导入验证。macOS命令使用前查可用性，不能假定存在GNU `timeout`。必要工具授权集中申请一次，等待用户期间保持已有工作；报告分别记录等待与工作区间。
- 透明单图先检查alpha与轮廓；精灵图先确认网格、帧序再切片。白底/纯色参考要保留角色内部同色部分：可从边界连通背景开始分割，修复抗锯齿白边，必要时手工遮罩。`tools/appearance/prepare-seed-frames.py`处理其声明的底板/网格，并非通用白底抠图器。复杂背景或重新创作时选适用图像工具，记录原图与加工方法。
- 基准图在棋盘、黑底、白底及目标显示大小下检查。眨眼/表情遮罩包含虹膜、高光、眼白、眼睑与抗锯齿边缘，并保护眉毛、发饰和脸部轮廓；保存睁眼/闭眼局部对照。自动遮罩不完整时直接修局部遮罩，不为单张图扩建通用识别算法。
- 动作可用图层、局部形变、绘制或稳定的基准图变换，按用户期望选择；短 idle 先证明呼吸、表情与首尾衔接。完整动作预览确认视觉质量，不把“使用缓动公式”作为流畅的唯一证据。
- 固定SDK根、工作区和输出包的绝对路径。默认包在工作区 `packages/`，用户指定其他位置时明确采用。重建脚本从脚本位置解析工作区，SDK根用显式参数或项目标记定位，不以固定父目录层数猜测；运行前显示解析后的输出位置。一次从不同当前目录的重建核对实际输出路径与清单/资源一致，之后复用该证据。

## 动画与布局合同

| 动作 | 播放/触发 | 制作建议 |
| --- | --- | --- |
| idle | 循环 | 呼吸、压缩/拉伸、回弹、轻倾和眨眼；首尾姿态衔接 |
| press | 一次 | 短压缩反馈，留出弹性回弹 |
| return | 一次 | 回城触发反馈；不要假装控制系统整屏转场 |
| depart / arrive | 跨屏桌面迁移 | 消失端收小/透明，出现端从小/透明展开 |
| edgeHide / edgePeek | 边缘迁移 | 缩回/探出，App同时施加边缘位置和裁切 |

App按最大画布边缩放到当前36–88 pt桌宠尺寸，非正方形会保持比例，anchor放到保存的位置。预览不能代表物理边缘裁切，需要实际检查五种放置。非 idle 动作播放最后一帧后保持，交互结束回到idle；迁移动作使用自定义动作时长分阶段。较长反馈会改变交互观感，建议0.2–0.7秒短动作。

鼠标跟随使用独立眼睛图层和方向头部图层。需先将这些部分从底图分离，再按API声明rect和移动幅度；不能给已有整张图片加一个开关就声称获得跟随。基础帧、眼睛、头部和每边资源需同时检查，防止双影。

### 边缘预演的实际坐标

当前SDK源码的几何合同如下；已安装App可能版本不同，最终组合效果仍由用户确认。App使用屏幕的 `visibleFrame`，桌宠中心距对应边缘默认8pt；可用behavior.edgeInset声明尺寸比例。`CompanionGeometry.petFrame` 的38/382坐标是420×420面板内的中心，不能把面板边界当作屏幕边界。

居中anchor、正方形画布、显示大小S时，默认屏内可见的画布比例约为 `0.5 + 8/S`；48pt约2/3，88pt约59%。菲比使用0.20×S的边距，配合0.64的边缘anchor保持露出头和上半身。预演先在稳定中心放置图像，再以屏幕边界裁切。非居中anchor按实际anchor计算，不套用此比例。

底边创作的角色在边缘放置期间按左−90°、右+90°、上180°、下0°转向，包括edgePeek/edgeHide、落位idle和点击/回城反馈，转向围绕稳定anchor。旋转不等于左右或上下镜像；预演仍需分别检查动作及落位姿态。包开发保持SDK只读，不用改anchor掩盖另一个边缘的裁切问题。

### 图标与显示清晰度

显式appIcon按原图使用，不要求复制默认图标的构图参数。优先突出头部/帽子等辨识特征，在18px及64px分别检查轮廓；与用户约定沿用默认探边风格时，再使用圆角底板、屏幕边线和同一角色。角色占比由小尺寸预览决定，默认图标的比例不是格式要求。

画布像素N、显示点数S、屏幕倍率r时，采样放大倍数是 `S×r/N`。例如128px在88pt@2x约放大1.375倍；在@1x是缩小。明确条件及清晰度取舍，不把点数直接当像素或声称固定放大倍数。

## 导出与内存预算

- 每帧32–512像素，必须PNG IHDR bit depth8/color type6（RGBA）；RGB、索引色、灰度、16bit、APNG均不接受。
- 每PNG≤4 MiB，唯一PNG像素总数≤16,777,216。manifest≤128 KiB，整包≤64 MiB，目录项≤2200，可包含引用的音效和单个JS，详见API。包内不能留未引用资源、预览视频、README或符号链接。
- 理论解码像素内存约唯一帧数×宽×高×4字节，再加独立图标宽×高×4字节，还包括NSImage/CGImage/缓存开销。压缩包大小不能代表常驻内存；先复用相同静止帧，再提高分辨率/FPS。
- 144张128×128唯一帧约9 MiB裸RGBA像素，1024软件图标另占约4 MiB；144张512×512会超出像素预算，校验拒绝。
- 外部生成/绘制的精灵图必须切成严格等大小帧并导出RGBA。自动颜色模式压缩成RGB/调色板时，需要重新转为RGBA导出。

生产格式通过后仍需检查背景透明与轮廓、idle/反馈动作的非空画面，以及完整动画的首尾/动作切换。迁移动作的透明端帧可按设计保留。帧差、质心/高度二阶差可帮助找异常，但单一比值或阈值不能证明“无跳变”“自然流畅”。复用适用工具或添加最小检查，不为每个角色重写完整格式校验器。

## 新能力的制作次序

先用一个静止基准+短idle证明角色，然后只增加用户要求的能力：独立边缘 → 分离跟随层 → 主题/气泡资源 → 音效 → bindings。只有条件逻辑无法用bindings表达时才加script；不要为呼吸动画写脚本。明确每边rotation/anchor，每个主题资源继承关系，以及默认交互是否覆盖用户偏好。所有动作、资源与API字段按API说明使用，拼写错误由校验器提示。

快速机制样本可由 `scripts/make-appearance-fixture.py` 生成，但其视觉仅用于API练习。最终造型应来自用户需求，不交付示例方块。基本验收只检查声明的新能力；实际音效、指针交互、Finder/Launchpad和多屏仍提供步骤交用户。

## 验收与回退

~~~sh
swift run --package-path /absolute/path/Char char-package-check skin /absolute/path/your.charpet
~~~

0表示包符合生产格式；1表示无效；2表示命令用法错误。开发者完成格式、完整预览及预算检查后，按[用户验收交付规范](plugin-user-acceptance.md#外观包应交付的完整步骤)提供实际包路径、GUI导入、桌面/四边、迁移、尺寸、Reduce Motion、重启与删除回退的完整文字步骤。用户自行操作；不为提供说明而要求解锁或代为打开App。没有多屏或系统权限的项目标为未运行，不能将包校验或离线预览当作产品交互通过。外部作者无需为了制作形象构建整个App。

生产导入先校验并复制、再次验证、同目录重命名提交安装。形象脚本经用户确认后通过隔离helper与Char事件/动作接口运行；不执行外部命令。重名ID拒绝导入，更新需先删除旧自定义包。删除当前包回到内置char.default；内置形象不能删除。用户数据在 ~/Library/Application Support/Char/skins，开发检查用临时目录，不直接修改该位置。

理论解码像素预算与实际进程成本分开报告；实际测量按[基本验收的性能分支](plugin-basic-acceptance.md#6-性能分开测量并保留原始样本)记录包ID、分辨率、唯一帧数、FPS、气泡与设置状态和样本时段。没有隔离宿主运行条件时提供估算并将实际成本列待测；不能承诺某帧率必然低功耗。宿主预算与实测范围见[性能说明](performance.md)，不作新形象实测数据。

运行图标、状态栏和安装图标随选中形象/主题同步。安装图标使用保留原Release、暂存修改、重新签名和验证的事务；可能需重建辅助功能授权，详见外观 API。实际验收检查Finder/Launchpad、切换/重启/删除恢复和小尺寸辨认度。

全部可自定义范围和宿主负责的行为见[外观能力范围](appearance-customization.md)。可选能力按完整API声明。

内置项目/安装图标与示例图标均由原生向量生成，修改后从仓库根目录运行 `scripts/generate-app-icons.sh` 再构建。图标按形象缓存，只在选择变化时更新，不增加动画计时器；1024图标的4 MiB是裸RGBA估算；界面按36/128/256像素解码，安装图标使用原文件。缓存预算与进程footprint分开计量。

有身体动画与原生跟随时，先制作短基准，再用共同帧索引和 `trackingFrames`/`tracking.states` 验证一条边，最后扩展主题与动作。官方完整参考见[菲比](../examples/appearance/feibi/README.md)。
