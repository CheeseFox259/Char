# 桌宠性能开销与优化方案

## 采样方法

macOS 26.5.1 ARM64，解锁状态。只采样 Char 自身，不读取 Agent 对话、不发送模型请求。CPU 使用进程累计 user+system 时间差除以墙钟时间，100% 表示一个核心。RSS 为进程驻留内存；这些数字不包含 WindowServer/GPU 开销。

```sh
pgrep -fl '/Char.app/Contents/MacOS/Char'
python3 scripts/profile-char.py <Char-PID> --seconds 20 --sample /tmp/char-profile.sample.txt
```

采样时记录版本、正常/演示模式、气泡数量、是否开过设置、设置当前是否关闭。不同模式不可直接相减为各组件 CPU 百分比。`sample` 的栈权重包含等待时间，父子栈不能相加，不能代替组件 CPU 占比。

关闭设置后的样本不再包含持续 `NSHostingView.layout`；CPU 不再升到约30%。RSS 仍高于首次启动，不能把释放视图说成所有缓存内存立即归还。正常观察比旧基线低，但不是隔离单项改动的受控实验，不能将全部变化归功于 stat。Kimi 读取路径仍偶见广泛属性读取，后续可沿同一最小元数据策略继续评估。

`a930824` 七气泡演示，设置打开/关闭两次后的续验窗口：CPU 8.69%（1.74 / 20.017 s），RSS 81,632 → 81,744 KiB。该窗口处于实际交互续验期间，不能标记为严格闲置或作为受控性能回归结论。随后用户仍报告物理鼠标延迟及 Space 气泡闪烁，因此该版本不是交互验收完成版本。

## 实际开销组成

1. **原生观察 IO。** 正常实例的样本多次出现 `LocalObservationPoller → FileManager.attributesOfItem → getxattr/listxattr`，只需要文件长度和 inode，却读取了扩展属性。正常实例比七气泡 fixture 更高，支持它是本机的重要额外开销；并不证明差值全部属于观察。
2. **持续图形提交。** 两种模式都包含 AppKit flush、Core Animation commit/display、桌宠绘制。60 Hz 变换更新和局部眼睛绘制仍有成本，渲染工作也发生在时钟回调返回后的提交中。
3. **重复窗口属性设置。** 旧演示的时钟样本中，不变的 `ignoresMouseEvents` 赋值仍产生窗口属性事务；该路径可以直接消除。
4. **隐藏的设置预览。** 开过设置再关闭后出现大量 `NSHostingView.layout`，从未开设置的同版本样本没有这一分支。关闭但保留带 TimelineView 的内容视图导致后台布局，修复优先级最高。
5. **焦点/窗口查询。** 正常实例存在 AX/CG 窗口信息查询和 IPC 等待。它影响检测延迟，但当前样本不足以给出准确 CPU 百分比。多屏模式的新 150 ms 检测成本须单独实测。

## 本轮已应用的优化

- 观察日志只用 `stat` 读取长度/inode；保留追加、半行、截短、替换与重新启用基线行为。
- 仅在布尔值变化时设置鼠标穿透属性。
- 缓存默认桌宠身体图像和气泡底图；动效保持局部变换及眼睛绘制。
- Reduce Motion 偏好通过系统通知更新，移出每帧/每气泡的重复偏好查询。
- 设置关闭时移除 HostingView 并释放窗口；重新打开创建新视图，保存的数据不受影响。
- 快照相同时不重复发送 `@Published`；单显示器跳过迁移焦点查询。观察轮询保持 500 ms，迁移检测独立。

## 后续优化计划（按证据排序）

| 优先级 | 改动 | 预期作用 | 代价/风险 | 验证标准 |
| --- | --- | --- | --- | --- |
| 1 | 默认身体与眼睛采用独立 Core Animation 层，闲置动作走关键帧，只有眼睛跟随/短动作更新 | 减少持续 AppKit raster/display 与主线程提交 | 中；必须保留弹性和命中区，不能降低动画流畅度换数字 | 同七气泡/同设置状态 20 秒采样；眼睛、悬停、边缘和回城实测正常 |
| 2 | 日志目录发现改为目录变化触发，并保留低频补扫 | 避免每 500 ms 遍历历史会话树 | 中；新文件、睡眠恢复、嵌套目录和停用重启不能漏报 | 同一真实日志树采样；新会话、轮转、睡醒及 Hook 合同仍通过 |
| 3 | 多屏检测采用前台应用 AX focused-window/move 事件，保留有限频率回退 | 减少常驻几何 IPC，同时及时跟随 | 中；需要处理授权缺失与应用不发事件 | 双屏同应用/不同应用迁移计时，记录通知→动画开始及完成，不只看常量 |
| 4 | 隐藏/锁定或减少动态效果时暂停不必要绘制；自定义形象按实际 fps 更新帧 | 减少后台及低帧率皮肤成本 | 小至中；显示恢复时必须重置时钟与命中区 | 锁定/隐藏、Reduce Motion、1 fps 与 60 fps 形象分别采样并恢复检查 |

没有承诺未经测量的节省百分比。先用同场景数据确认剩余主导路径，再执行下一项；避免同时改多个变量导致结果无法解释。
