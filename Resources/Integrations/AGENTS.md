# Char 集成插件包开发指令

在此目录开始任务时，按用户当前需求交付完整 `.charintegration` 包。名称、目标软件、运行方式和能力由任务给出；不预设具体插件。缺少必要目标时集中提问，同时查证可独立进行的内容。

以下路径相对仓库根，命令从根执行。先读根 `CONTEXT.md`、`docs/plugin-development.md`、`docs/integration-plugin-format.md`、`docs/capability-adapter-protocol.md`、ADR 0008，以及生产清单校验和适配器宿主。

## 开发流程

1. 确认目标真实 bundle ID、CLI/Desktop、监控信号、导航精度和客户端安装位置，附官方/已安装客户端证据。区分“能配置的旧能力”与“需要实现的客户端接口”。应用级来源无需额外插件。
2. 新能力使用 schemaVersion3，选择唯一 ID、动态 workEnd、clientInterface、版本和 monitor/visit/origin/lifecycle；旧 v1/v2 只用于已有能力。不要用某个已有 Agent 身份冒充新客户端，不要求用户重编译 Char。
3. 使用 scripts/new-capability-plugin.py 可生成骨架，但骨架不是完成品。必要适配器和客户端扩展按 integrations/AGENTS.md 实现后放入包；正式包包含实际入口和依赖，全部路径包内相对且无符号链接，整包≤8MiB；图标按生产 PNG 契约校验。说明、fixture、生成器留在包外。
4. 运行时代码只走进程协议，不加载第三方动态库进宿主。stdout 不含调试文字；上下文由宿主注入。configuration 描述配置根/环境，不保存凭证。独立进程有当前用户权限，不宣称沙箱隔离。
5. hello/inspect 必须真实；安装升级卸载只管理所属记录，备份并幂等，引用稳定事件入口。inspect 区分配置可用与需要重载，不能凭启用开关宣称正常监控。导入不自动安装客户端 Hook。
6. 准确导航需要可靠对象身份与实际确认；应用激活是 fallback。origin token 绑定原 PID/适配器实例，临时查询失败保留重试。首次/最近/禁用起点、过滤、排序、快捷键和动画由宿主管理。
7. 用 swift run char-package-check integration <包目录> 校验实际交付包；再对可信代码用 char-plugin-check inspect 和 replay 检查协议/事件。修复至通过，不把格式通过当真实监控证明。
8. 有授权后在隔离注册表验证导入→新活动气泡→点击访问→回城→禁用→同ID更新→删除；验证自检、安装/更新/卸载、精度反馈和失败恢复。保留原用户配置，删除可选择不卸载集成。新增进程成本和清理必须测量。

## 完成标准

交付可导入包、源码位置、能力矩阵、运行时依赖、配置项、证据、安装/升级/卸载/回退方法、实际测试结果和未验收项。各项分别记录格式校验、事件回放、模拟导航、真实客户端验收。缺失信号另列，不编造具体对象聚焦和检测范围。修改格式/协议时同步生产校验、测试与文档。发布依用户授权执行。
