# Char 集成包开发指令

按当前用户的软件和使用方式交付 `.charintegration`。本目录保存内置资源；第三方包在用户指定目录或 `integrations/<软件slug>/` 开发，不要求成为 Char 源码的一部分。

## 1. 选择开发分支

先读 SDK 根的 **`docs/plugin-development.md`**，以格式和协议文档为契约。

- **新增客户端能力**：读取 `integrations/AGENTS.md` 并按完整流程实施；使用当前进程适配器，继续到实现、打包和基本验收。
- **组合已有内置能力**：按 `docs/integration-plugin-format.md` 制作 schemaVersion 3 的配置包。仅查询需要的已有身份/字段；没有对应内置能力时提供进程适配器。
- **要求成为内置资源**：在用户授权范围内写入本目录；普通第三方开发保持 SDK 只读。

首轮确定工作目录、身份与范围并建立可校验包。保留已有文件；源码/生成器/测试/说明留在包外，不以生成清单作为新增能力完成。

## 2. 实现和打包

名称、bundle、id/workEnd、clientInterface 来自目标身份；CLI/Desktop 分别打包。按 **`docs/plugin-icon-sourcing.md`** 查找本地官方图标，失败后网上核实，再请用户上传。图标来源准确与 PNG 可解码分别检查；承载终端或扩展图标不代表 Agent，CLI 角标由宿主绘制。

包使用相对路径，包含清单、运行所需代码/依赖与图标；不含符号链接，≤8 MiB。进程适配器只声明已实现能力，路径来自宿主上下文/字符串配置，stdout 只有版本1协议。无精确对象时省略 origin，应用级回城由宿主提供。无需修改 WorkEnd/ReturnAdapter 枚举、宿主构建或支持列表。

完成条件：完整包由唯一源码生成，身份/图标/能力与实现一致，运行时依赖和权限有查证。

## 3. 基本验收与交付

按 **`docs/plugin-basic-acceptance.md` 的执行策略**先做快测，失败只重跑相关组、最终完整包检查一次。源码相同的双包复用机制证据，每包身份/配置与路由分别检查；原生交互框架为按需检查。执行适用分支：配置包做格式、身份、图标检查；含进程适配器的包再做协议、监控调度、维护所有权、共享资源和导航检查。SDK 命令支持 `--package-path`，外部作者无需构建 App 或修改主仓库全量脚本。成本按实际进程数记录，清理隔离测试资源。

按 **`docs/plugin-user-acceptance.md`** 提供填好的 `USER-ACCEPTANCE.md`，最终回复直接给出完整 GUI 导入、启用、加载、测试、热维护与恢复步骤。用户无需自己打命令。集成包同 ID 完整重导入是更新，旧适配器/准确锚点会失效；不要直接改已安装副本。

完成条件：包和基本验收证据已交付，待用户验证项明确列出。默认由用户操作真实客户端；给说明时无需打开应用、请求解锁或代测。只有明确请求才进行相关准备或代测。发布和持久环境写入按当前授权处理；配置就绪、原生加载与完整产品通过分别报告。
