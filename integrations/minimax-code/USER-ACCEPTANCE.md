# MiniMax 用户验收 · 无需终端命令

## 准备与导入

1. 安装 Char、Warp 与 MiniMax Code。CLI 端需要你已经能在 Warp 中正常使用 MiniMax Code CLI；只验桌面端时不用准备 CLI。Node 为插件低频维护依赖，缺失时先安装当前可用的 Node 发行版。
2. 下载 Release 的示例 ZIP 并解压。在 **Char 设置 → 插件 → 导入插件…** 选择 `Examples/minimax-code-cli.charintegration`，再导入 `Examples/minimax-code-desktop.charintegration`；仓库用户从本目录 `packages/` 选对应目录。
3. 信任代码后打开需要的开关。两行应分别显示 MiniMax 图标，CLI 多一个终端角标。
4. 新用户用每行维护菜单 → **安装**，随后让客户端加载 Hook：CLI 用平时的方式新开 MiniMax 会话；Desktop 完全退出再打开。再对两行 **自检**，应显示配置可用、Hook 版本 1.0.0。
5. 已有 1.0.0 Hook 的用户更新包只做同 ID 导入和自检，无需重装 Hook。配置保留；只有明确提示原生集成版本变化时才更新集成并重载客户端。

## 使用

- 两端分别自然完成一轮，切到另一应用观察气泡；审批时应显示等待审批，结束时显示轮次结束。支持范围依客户端原生信号，不要求制造未支持的失败类别。
- 点击 CLI 气泡激活 Warp，Desktop 气泡激活 MiniMax Code。当前是应用级跳转，不承诺具体会话。成功后气泡清除并播放破碎；Ctrl+B 回到保存的起点。
- 设置 → 性能开启采集，等至少 2 秒。两端原生常驻进程在本机约 10 MiB RSS/端；短暂 Node helper 不包含在这一行，实际值受系统影响。

## 热维护与恢复

- 关闭一端后不再观察该端，另一端保持；重新打开只观察新事件。
- 同 ID 导入更新无需重启 Char，保留启停状态。保留旧包，若需回退，直接从设置导入旧包。
- 删除可选“仅删除插件”或“卸载集成并删除”。后一项只清理所属资源；另一端仍拥有共享 Hook 时继续保留。最后一端删除后保留用户配置、会话、其他插件和无关诊断文件。
- 恢复：导入 → 安装（需要时）→ 客户端加载 → 自检。

反馈：`导入/图标___；自检___；CLI___；Desktop___；跳转/回城___；性能___；热更新/删除___`。失败时提供端、时间、状态图标悬停说明或截图；不必运行日志命令。
