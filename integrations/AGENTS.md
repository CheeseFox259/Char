# Char 原生集成开发

在本目录开始任务时，开发用户指定客户端的提醒协议或准确回城适配器。客户端、运行方式和功能目标从当前任务获取，完成可验证的实现与安装交付。

以下仓库路径相对仓库根目录；构建与校验命令从仓库根目录运行。

## 能力查证

阅读根目录 `CONTEXT.md`、`docs/plugin-development.md`、`docs/signal-feasibility.md` 和 `docs/adr/0007-unified-integrations-and-free-origins.md`。查目标官方事件、日志/API或已安装源码；记录根会话身份、CLI/Desktop 区分，以及各提醒原因的可靠证据。未提供必要客户端/目标时集中提问。没有证据的状态明确留空，不根据正文或沉默推断，不为测试自行发起模型请求。

## 实现

- 新工作端扩展 `WorkEnd`，检查全部穷举分支、内置清单、图标/CLI角标和 fixture；配置包只选择已编译能力。
- 提醒通过 `CharObservations` 或本目录原生扩展产生 `ObservationEvent`，沿用 `CharHook` 的编码、稳定原生根身份和真实时间。只记录必要元数据。
- 保持 EOF 启动基线、完整新行、批次排序、重复/乱序水位、半行、截短/轮转、符号链接根变化、子会话过滤和启停代次语义。保持原客户端返回值与错误行为。
- 准确回城扩展 `ReturnAdapter`、清单校验和 `CharPlatform` 捕获/存活/匹配/聚焦路径。opaque token 绑定原进程；实际确认准确聚焦后返回 exact，应用激活返回 fallback。临时失败保留锚点重试，确定关闭才失效；连续访问保留首次往返起点。
- 使用客户端正式接口和显式授权。原生扩展安装与 Char 配置导入分别提供步骤，备份用户配置，支持卸载恢复。

## 验证与交付

先用真实协议样本构造会失败的临时 fixture，覆盖本次涉及的身份、状态、恢复/关闭、乱序和启停边界。运行 `scripts/check.sh`、`scripts/build-app.sh`、应用 `--smoke` 与签名检查。具备环境和授权后走实际客户端路径；将 fixture、模拟跳转、真实验收分开报告。

交付实现、可导入配置包、能力矩阵、安装/卸载文档和实际检查结果。受官方信号或接口限制的能力附证据及后续方案；完成当前已可验证范围。远端发布遵循当前用户授权和仓库规则。
